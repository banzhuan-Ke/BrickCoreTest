# 执行器安装指南（Windows / macOS）

本文说明如何在 **Windows** 或 **Mac** 上安装 BrickCore 执行器，并连接测试平台。

| 系统 | 安装包 | 适用场景 |
|------|--------|----------|
| **Windows** | `BrickCoreRunner.zip`（约 800MB） | 桌面客户端：Web 自动化、App 自动化、录制、实时画面、压测 |
| **macOS（Apple 芯片）** | `BrickCoreRunner-mac-arm64.zip` | 命令行执行器：Web 自动化（有头/无头） |
| **macOS（Intel）** | `BrickCoreRunner-mac-intel.zip` | 同上，**与 arm64 包不可混用** |

---

## 获取安装包

| 方式 | 说明 |
|------|------|
| **网盘下载（推荐）** | 使用管理员提供的百度网盘 / 阿里云盘链接 |
| **平台下载** | 登录平台 → **Web 自动化 → 设备管理** → **网盘下载** |

> Windows 与 Mac 安装包**不能混用**。  
> Mac 终端执行 `uname -m`：`arm64` 用 arm64 包，`x86_64` 用 intel 包。

### 网盘可选附件（App 自动化 / 录屏）

安装包内**不含**下列工具，需要时请从网盘一并获取：

| 文件 | 用途 |
|------|------|
| **`ffmpeg-release-essentials.zip`** | App 用例录屏 |
| **`scrcpy-win64-vX.x.zip`**（可选） | App 录屏备选方案 |
| **platform-tools**（含 `adb`） | App 自动化；连接 Android 真机 / WiFi / 模拟器 |

> ffmpeg 请选 **release builds** 中的 **essentials** 包，不要下 `ffmpeg-tools.zip`（不含 `ffmpeg.exe`）。

## 一、Windows 安装与使用

### 1. 系统要求

- Windows 10 / 11（64 位）
- 无需单独安装 Python（安装包内已含运行环境）
- 磁盘建议预留 **2GB 以上**

### 2. 解压

1. 将 `BrickCoreRunner.zip` 解压到任意目录（路径尽量**不含中文与空格**）
2. 确认目录完整（**不可只复制 exe**）：

```
BrickCoreRunner/
├── BrickCoreRunner.exe    # 双击启动
├── _internal/             # 必须与 exe 同目录
├── runner/                # 执行引擎
└── VERSION.txt
```

### 3. 连接平台并上线

1. 双击 **`BrickCoreRunner.exe`**
2. 点击 **管理服务器环境**，添加平台地址，例如：
   - `http://192.168.1.100`
   - `https://test.example.com`
   - 使用域名或 Nginx 时填 **80** 端口，**不要写 `:8000`**
3. 使用平台账号 **登录**
4. 勾选需要的能力（**Web** / **App** / **接口代发** / **压测**）→ 填写 **设备名称**（如 `Windows-张三`）→ 点击 **上线**
   勾选接口代发或压测时，还需选择 **所属项目**（与平台顶部项目一致）。二者共用同一执行机进程。
5. 在平台 **Web 自动化 → 设备管理** 中确认设备状态为 **在线**

### 4. 常用操作

| 操作 | 说明 |
|------|------|
| 下线 | 点击 **下线** 后再切换环境或关闭程序 |
| 检查更新 | 对比平台推荐版本；**优先一键加密增量更新**（覆盖后自动重启）。无增量或底座变更时下载完整 zip **整目录覆盖**（先关闭客户端） |
| 开机自启 | 在 **设置** 中开启 |
| 有头调试 | 执行 Web 用例时本地会弹出浏览器；可在 **设备管理 → 实时画面** 查看桌面 |

### 5. 更换平台地址

在 **管理服务器环境** 中切换或修改地址 → **下线** → 重新 **登录 / 上线**。

## 二、App 自动化（仅 Windows）

执行 App 用例前须满足：

- 客户端上线时勾选 **App 自动化**
- 本机已安装 **adb**（platform-tools **30+**，推荐 34+），`adb devices` 中至少一台状态为 **`device`**
- Android 设备已开启 **开发者选项 / USB 调试**（模拟器同理）
- 连接方式三选一：**USB 数据线**（最稳）、**WiFi 无线调试**、**Android 模拟器**（MuMu 等）

> 平台通过 Runner 本机 `adb` 识别设备，不区分 USB / WiFi；serial 含 `:`（如 `192.168.1.8:5555`）时设备管理会显示连接方式 **wifi**。

### 1. 安装 adb

1. 解压网盘中的 **platform-tools** 到例如 `E:\soft\platform-tools`（路径勿含中文）
2. 将该目录加入系统环境变量 **Path**，并排在 **scrcpy 等自带 adb 目录之前**
3. 验证（建议版本 ≥ 30，用于无线配对）：

```powershell
where.exe adb
adb version
adb devices
```

列表中设备状态为 `device` 即表示连接正常。

**避免多 adb 冲突**：若 Path 中同时有 scrcpy 自带的 `adb.exe`，配对或连接异常时先执行：

```powershell
adb kill-server
E:\soft\platform-tools\adb.exe start-server
```

后续无线调试命令建议统一使用 **platform-tools 全路径** 的 `adb.exe`。

### 2. 连接 Android 设备

任选一种方式，最终目标均为 `adb devices` 出现 `device`。

#### 2.1 USB 数据线（推荐）

1. 手机开启 **USB 调试**，用数据线连接 PC，在手机上允许调试授权  
2. 执行 `adb devices`，应看到设备 serial（如 `ABCD1234`）且状态为 `device`  
3. 拔线前若需切 WiFi，见 [2.2](#22-wifi-无线调试android-11)

#### 2.2 WiFi 无线调试（Android 11+）

**前提**：PC 与手机 **网络互通**（同一 WiFi 且路由器 **未开启 AP 隔离**，或 **手机开热点、PC 连热点**）。  
若 `ping 手机IP` 提示「无法访问目标主机」，请先换热点或关闭 AP 隔离，否则 `adb pair` 会报 `protocol fault`。

**方式 A：无线调试 + 配对码（全程可不用数据线）**

1. 手机：**设置 → 开发者选项 → 无线调试** → 开启  
2. 点 **「使用配对码配对设备」**，记下弹窗中的 **WLAN 配对码**、**配对 IP:端口**（端口**每次随机**）  
3. PC（弹窗保持打开，码过期需重新获取）：

```powershell
adb kill-server
E:\soft\platform-tools\adb.exe start-server
E:\soft\platform-tools\adb.exe pair 192.168.x.x:配对端口 123456
```

4. 配对成功后，在无线调试 **主界面**（非弹窗）查看 **IP 地址和端口**（连接端口，相对稳定），执行：

```powershell
E:\soft\platform-tools\adb.exe connect 192.168.x.x:连接端口
E:\soft\platform-tools\adb.exe devices
```

应看到 `192.168.x.x:连接端口    device`。

**方式 B：USB 开启 tcpip 后再 WiFi（Android 10 或配对失败时）**

```powershell
# 须先 USB 连接且 adb devices 为 device
E:\soft\platform-tools\adb.exe tcpip 5555
E:\soft\platform-tools\adb.exe connect 192.168.x.x:5555
E:\soft\platform-tools\adb.exe devices
```

- **手机重启后** 方式 B 通常需重新 USB 执行一次 `tcpip 5555`  
- 方式 A 在重启后一般只需重新 `adb connect`（极端情况重新配对）

**WiFi 日常维护**

| 场景 | 操作 |
|------|------|
| 手机重启 / 换 WiFi | 重新 `adb connect IP:端口`（或重新配对） |
| 定时任务 / 无人值守 | 保持 Runner 在线；确保 adb 仍为 `device` |
| 公司 WiFi ping 不通手机 | 改用手机 **个人热点** 或 USB |

#### 2.3 Android 模拟器（MuMu、夜神等）

平台将模拟器视为普通 adb 设备，流程与真机相同。最终目标仍是 `adb devices` 出现状态为 **`device`** 的一行。

**MuMu 等设置要点**（以「设备设置」为例）：

| 位置 | 建议 |
|------|------|
| **开发者选项 → ADB 调试** | 开启（可选「仅本地」或「本地和远程」）；这是必开项 |
| **网络 → 网络桥接** | **保持关闭**。本地 `adb` 不需要桥接，也与平台连接无关 |
| **机型** | 与 adb 无关，无需为自动化改机型 |
| **其他 / 多开管理器** | 部分版本在此显示 ADB 端口；找不到端口时见下方「端口找不到」 |

**连接方式（两种都常见）**：

1. **已自动出现设备**（无需 `adb connect`）  
   部分模拟器（含部分 MuMu 实例）开启 ADB 后，本机直接可见类似：

   ```text
   List of devices attached
   emulator-5554    device
   ```

   此时 **不必** 再找端口或执行 `adb connect`；平台侧 `app_udid` 即为该 serial（如 `emulator-5554`）。

2. **需按端口连接**  
   在模拟器设置中记下 ADB 端口后：

   ```powershell
   E:\soft\platform-tools\adb.exe connect 127.0.0.1:7555
   E:\soft\platform-tools\adb.exe devices
   ```

   常见端口：`7555`（偏老 MuMu）、`16384` / `16416` 等（MuMu 12 多开，以设置页或管理器为准）。

**端口找不到时**：

1. 先执行 `adb devices`——若已有 `emulator-XXXX` 且为 `device`，说明已连通，**不用找端口**  
2. 再看 **其他**、**多开管理器** 是否标注端口  
3. 仍无线索时可试常见端口，或用本机监听排查：

   ```powershell
   adb connect 127.0.0.1:16384
   adb connect 127.0.0.1:7555
   adb devices
   ```

后续步骤：

3. 在模拟器内 **安装被测 APK**，包名与用例中 `app_id` 一致  
4. 多台 adb 设备同时在线时，Runner 默认取 `adb devices` **列表第一台**；建议只保留一台 `device`，或在平台执行/定时任务中 **指定 Runner 设备**

**模拟器注意**：部分 App 会检测模拟器并拒绝运行；性能低于真机，图像识别步骤可适当加长等待；H5 WebView 调试策略与真机相同。

### 3. 首次初始化 uiautomator2（每台设备一次）

在 **adb 已连通**（USB / WiFi / 模拟器均可）后，于 BrickCoreRunner 目录执行：

```powershell
cd <BrickCoreRunner>\runner
.\venv\Scripts\python.exe -m uiautomator2 init
```

按提示在设备上允许安装 ATX 代理。若 serial 从 USB 变为 `IP:端口`，对 WiFi serial 再 init 一次更稳妥。

**判定是否成功（重要）**：日志中若出现 `u2.jar` 已推送、`http server listening on *:9008`（或等价 ping 成功），则 **自动化主体已就绪**，可继续上线 Runner。

**MuMu 等常见：末尾报 `InputIMEError: install AdbKeyboard ime failed`**

- 原因：模拟器常禁止 `adb shell ime enable` / `ime set`（提示 *disabled for security reasons*），第三方 **AdbKeyboard** 无法登记为输入法；`init` 会在最后一步失败并退出。  
- **可忽略**：点击、滑动、断言、截图以及多数控件 `set_text` 输入 **不依赖** AdbKeyboard。不要反复重跑 `init` 指望消除该报错。  
- 若个别「特殊字符 / 键盘注入」步骤失败：可尝试在模拟器 **开发者选项** 打开 Root 后重试；仍不行则改用真机，或在模拟器系统设置里手动启用已安装的 AdbKeyboard（若系统允许）。  
- 日志中的 `apkutils is not installed` 可忽略，不影响主流程。

### 4. Runner 上线与平台确认

1. 打开 **BrickCoreRunner**，勾选 **App 自动化** → 登录 → **上线**  
2. 平台 **设备管理** 中该 Runner 应显示 **在线**，且 **`app_udid`** 为当前 adb serial（WiFi 为 `IP:端口`，连接方式 **wifi**）  
3. **App 自动化 → 元素探查 / 执行用例** 中选择该在线 Runner 进行验证

### 5. App 用例录屏（可选）

用例或套件开启 **录屏** 时，执行器会自动尝试多种录屏方式；其中 **exec-out** 与 **截图合成** 需要本机安装 **ffmpeg**。

#### 安装 ffmpeg

1. 解压网盘中的 **`ffmpeg-release-essentials.zip`** 到例如 `C:\tools\ffmpeg`
2. 确认存在 `C:\tools\ffmpeg\bin\ffmpeg.exe`
3. 将 **`...\ffmpeg\bin`** 加入系统 **Path**
4. 新开 PowerShell 验证：

```powershell
ffmpeg -version
```

能显示版本信息且正常退出即可。然后 **完全退出 BrickCoreRunner 再重新启动**。

录屏成功时，执行日志中会出现：`App 录屏已启动（模式: exec-out-h264）`。

#### 可选：安装 scrcpy

scrcpy 为录屏备选，**不安装也可执行用例**（有 ffmpeg 时通常已够用）。

**在线安装（可访问外网时）：**

```powershell
winget install --id Genymobile.scrcpy -e
```

**离线安装（网盘 zip）：**

1. 解压 **`scrcpy-win64-vX.x.zip`** 到例如 `C:\tools\scrcpy`
2. 确认目录内有 **`scrcpy.exe`**
3. 将该目录加入 **Path**
4. 验证：`scrcpy --version`

> 须先安装 adb 且 `adb devices` 为 `device`（USB / WiFi / 模拟器均可）。安装后请重启 BrickCoreRunner。  
> 请使用官方 **scrcpy**，不要使用 Scrcpy GUI、QtScrcpy 等第三方壳。

## 三、macOS 安装与使用

### 1. 系统要求

- Apple 芯片用 **arm64** 包，Intel 芯片用 **intel** 包
- 请在 **Mac 本机** 解压 zip（勿在 Windows 解压后再拷贝）

### 2. 解压

**Apple 芯片：**

```bash
unzip BrickCoreRunner-mac-arm64.zip
cd BrickCoreRunner-mac
```

**Intel：**

```bash
unzip BrickCoreRunner-mac-intel.zip
cd BrickCoreRunner-mac
```

目录结构：

```
BrickCoreRunner-mac/
├── connect-mac.sh
├── start-mac.sh
├── runner/
└── VERSION.txt
```

### 3. 首次连接平台

```bash
chmod +x connect-mac.sh start-mac.sh
./connect-mac.sh
```

按提示输入平台地址、账号、设备名称。成功后会在本机生成 `runner/.env`（压缩包内原本没有，属正常）。

平台地址使用 **80** 端口时**不要加 `:8000`**。

### 4. 启动执行器

```bash
./start-mac.sh
```

新版本 `start-mac.sh` 会在启动时自动给内置 Chromium / `ffmpeg-mac` 补可执行权限，并尝试清除隔离标记。若仍报 `EACCES`，见下方「macOS → 浏览器启动失败」。

在平台 **设备管理** 中确认 **在线**。

### 5. 有头模式（可选）

如需执行时弹出浏览器窗口，在 `runner/.env` 中设置：

```env
HEADLESS=false
```

### 6. 更换平台地址

删除或改名 `runner/.env` 后重新运行 `./connect-mac.sh`，或手动编辑其中的 `BASE_URL` 等项。

> macOS 安装包当前仅支持 **Web 自动化**，不含 App 自动化与 Windows 图形客户端。

## 四、网络要求

执行器电脑需能访问平台（具体地址以管理员告知为准）：

| 端口 | 用途 |
|------|------|
| 80 | 平台 API |
| 25672 | 消息队列 |
| 26379 | 缓存服务 |
| 9200 | 文件存储（截图、录屏上传等，若平台已启用） |

无法上线时请联系平台管理员检查网络与防火墙。

## 五、常见问题

### Windows

| 现象 | 处理 |
|------|------|
| 双击 exe 闪退 | 确认 `_internal/`、`runner/` 与 exe 在同一目录；重新完整解压 |
| 无法登录 / 无法访问服务器 | 地址勿带 `:8000`；浏览器访问 `http://<平台IP>/runner/health` 应正常 |
| 设备不上线 | 检查 25672、26379 端口是否放行；先下线再重新上线 |
| 需要升级 | 下载最新 zip，关闭客户端后整目录覆盖 |
| App 录屏失败 | 安装 ffmpeg 并加入 Path，重启客户端 |
| App 图像步骤失败、元素库无预览图 | 在 **App 元素库** 中重新上传识别小图并保存 |
| `adb devices` 无设备 | 检查 USB 调试、驱动与授权；WiFi 是否 `adb connect`；模拟器先看是否已有 `emulator-XXXX`，否则 `adb connect 127.0.0.1:端口` |
| `adb pair` 报 `protocol fault` | 多为 PC 与手机网络不通（AP 隔离）；改手机热点或 `ping` 手机 IP；统一用 platform-tools 的 adb 并 `adb kill-server` |
| WiFi 连上后 Runner 无 `app_udid` | 确认 `adb devices` 为 `device` 后 **下线再上线**；心跳会刷新 UDID |
| 模拟器 `unauthorized` | 在模拟器内确认 adb 调试授权；重启模拟器后重新 `adb connect` |
| 模拟器找不到 ADB 端口 | 先 `adb devices`；已有 `emulator-XXXX device` 则无需端口。否则看「其他 / 多开管理器」，或试 `16384`/`7555` |
| `uiautomator2 init` 报 AdbKeyboard / IME 失败 | 若日志已有 u2 监听 `9008`，主体已就绪，可忽略并上线 Runner；见上文 §3 |
| `ime enable/set` 提示 security reasons | MuMu 等安全策略，属预期；不必强行启用 AdbKeyboard |
| 多台 adb 设备选错 | 断开多余设备或只保留一台 `device`；定时任务指定 **执行设备** |

### macOS

| 现象 | 处理 |
|------|------|
| 没有 `runner/.env` | 先执行 `./connect-mac.sh` |
| 在 Windows 上解压报错 | 请在 Mac 上直接解压原 zip |
| 设备不上线 | 检查 `.env` 中地址与端口；重新 `connect-mac.sh` |
| 浏览器启动失败 / `ffmpeg-mac` `EACCES` | 新包用 `./start-mac.sh` 即可自动补权限；旧包手工执行：`chmod +x runner/browsers/ffmpeg-*/ffmpeg-mac` 与 Chromium，必要时 `xattr -dr com.apple.quarantine runner/browsers` |
| 提示缺少浏览器 | 在 `runner` 目录执行：`./venv/bin/python -m playwright install chromium` |

### Web 自动化浏览器说明

Web 自动化使用安装包自带的 **Chromium**，**无需**另行安装 Chrome，与您日常使用的浏览器互不影响。

## 六、使用流程简述

1. 安装并解压执行器 → 连接平台 → **上线**
2. 在平台 **Web 自动化** 或 **App 自动化** 中选择用例 → **运行** → 选择本机在线设备
3. 执行结束后在 **测试报告** 中查看步骤、截图与录屏（若已开启）
4. 使用完毕建议点击 **下线**

如有其他问题，请联系平台管理员。
