# 项目与环境配置

各测试模块共用 **项目、环境、测试目录** 三层配置。建议新用户先完成本节再编写用例。

## 项目管理

**路径**：**项目配置 → 项目管理**

### 新建项目

1. 点击 **新建**，填写 **项目名称**（必填）
2. 保存后，在顶部导航 **选择该项目**，后续数据均归属此项目

### 编辑项目

可维护：

| 字段 | 说明 |
|------|------|
| 项目名称 | 显示在顶部项目下拉中 |
| 项目全局变量 | JSON 键值对，所有环境共享的默认值 |

### 项目全局变量 vs 环境变量

执行接口/UI 用例时变量合并优先级（后者覆盖前者）：

```
项目全局变量 < 环境全局变量 < 用例/计划传入的变量
```

**推荐维护入口**：**环境配置 → 项目共享变量**（与「项目管理 → 编辑」写同一份数据，环境页更易发现）。

## 环境配置

**路径**：**项目配置 → 环境配置**

页签：

| 页签 | 说明 |
|------|------|
| **环境列表** | 各环境 Host、环境变量；**同步变量**（批量增删键 / 从某环境复制值）；**查看引用** |
| **项目共享变量** | 项目级默认值；账号密码等差异项请写在各环境 |

每个项目可配置多套环境（开发、测试、预发等）。

### 新建环境

| 字段 | 说明 |
|------|------|
| 环境名称 | 如「测试环境」「SIT」 |
| Host | 被测系统根地址，如 `https://test.example.com`（末尾勿多余斜杠） |
| 全局变量 | 键值表格或 JSON 高级模式；支持 **描述**、**敏感** 标记 |

### 跨环境同步变量

环境列表 → **同步变量**：

| 操作 | 说明 |
|------|------|
| 批量新增键 | 目标环境缺少该键时补上（默认空值），已有不覆盖；适合「各环境都要有、值再分别填」 |
| 批量删除键 | 从目标环境删除勾选键（系统保留键不动） |
| 同步值 | 从源环境复制勾选键的值到目标；可勾选是否覆盖已有值 |

### 变量引用

**查看引用**：输入变量名，列出接口 / Web / App / SQL / 压测等引用处，并可跳转。仅扫描配置中的 `${{变量名}}` 明文（动态拼装名无法覆盖）。

### 环境变量编辑

**路径**：环境列表 → **编辑** → 环境变量区域

| 列 / 能力 | 说明 |
|-----------|------|
| 变量名 | 引用时写 `${{变量名}}` |
| 变量值 | 支持 Faker 表达式，如 `faker.random_int(min=1,max=99)` |
| **描述** | 用途说明；在 **插入变量**、变量预览中可见，便于团队辨认 |
| **敏感** | 名称含 token/password 等会自动标记；值以密码框显示 |
| 键值表格 / JSON | 表格适合日常维护；JSON 适合批量导入导出 |

项目 **全局变量** 与环境页「项目共享变量」为同一配置，优先级低于环境变量。

### 变量引用语法

在接口用例、计划、部分 UI 配置中使用：

```
${{变量名}}
```

**示例**

| 键 | 值 | 用途 |
|----|-----|------|
| base_url | https://test.example.com | 与 Host 配合 |
| admin_user | test01 | 登录账号 |
| admin_pwd | *** | 登录密码（敏感信息注意权限） |

修改环境变量后，**下次执行**自动生效，无需重启服务。

## 测试目录

**路径**：**项目配置 → 测试目录**

统一维护 **UI 与接口** 共用的目录树（已替代原「模块管理」「接口分类」「用例分类」）。

1. 按业务子系统建立多级目录（如「知识库 → 场景知识库」）
2. 页顶查看目录数、接口数、用例数、套件数等 **统计卡片**
3. 新建用例/套件/计划时选择 **所属目录**（树形选择器）
4. 各列表页左侧 **目录树** 按子树筛选数据

详细说明见 **测试目录** 章节。

## 通知配置（可选）

报告与失败告警在 **系统管理** 中按项目配置，不在项目管理页内：

| 步骤 | 操作 |
|------|------|
| 1 | **系统管理 → SMTP配置**（若用邮件） |
| 2 | **系统管理 → 通知配置** → 选择项目 → 添加渠道 |
| 3 | 配置邮件/钉钉/企微/**飞书**，可开启「套件/计划成功后自动推报告」 |

详见 **系统管理** 章节。

## 配置检查清单

- [ ] 已创建目标项目并在顶部选中
- [ ] 至少一套环境，Host 可访问
- [ ] 登录类账号等常用变量已写入环境或项目变量
- [ ] 测试目录树已按需建好，主要资产已选择所属目录
- [ ] （可选）通知渠道已配置并测试发送

完成后可进入 **Web 自动化**、**接口自动化** 或 **AI 测试** 模块。

## 常见问题

**Q：顶部选不了项目？**  
账号可能没有项目权限，联系管理员分配角色。

**Q：执行时变量没替换？**  
检查是否写成 `${{name}}` 双花括号；确认变量在当次执行的环境中已配置。

**Q：Host 和 base_url 都要填吗？**  
Host 为环境主地址；若用例里用 `${{base_url}}` 拼路径，建议在环境变量中显式配置 `base_url`。

**Q：测试目录统计全是 0？**  
目录本身不包含数据，需在接口/用例/套件上设置 **所属目录**；见 **测试目录** 章节。
