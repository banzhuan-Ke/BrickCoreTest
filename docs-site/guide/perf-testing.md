# 性能测试

## 适用场景

对 HTTP 接口进行压力测试：吞吐量、响应时间分位、错误率；支持多接口混合场景、梯度加压、分布式 Worker。

## 使用前准备

| 项 | 说明 |
|----|------|
| 项目与环境 | 已配置，Host 指向压测目标（**勿对生产误压**） |
| 接口用例 | 在 **接口自动化 → 用例管理** 中维护被压接口 |
| Worker（可选） | 分布式压测需启动 `perf_worker.py` |

## 基本流程

```
场景管理 →（启动 Worker）→ 执行压测 → 执行记录 / 报告对比
         ↘ 定时压测（可选）
```

## 场景管理

**路径**：**性能测试 → 场景管理**

### 新建场景

**压测模式**

| 模式 | 说明 |
|------|------|
| **固定模式** | 固定并发用户数 + 持续时长（秒） |
| **循环模式** | 固定并发 + 固定循环次数 |
| **梯度模式** | 多阶段：每阶段不同并发与时长，模拟阶梯加压 |

**通用参数**

| 参数 | 说明 |
|------|------|
| 并发用户数 | 1～1000（视环境与 Worker 能力） |
| Ramp-up | 爬坡时间（秒），用户逐步启动 |
| 目标 Host | 可覆盖环境 Host |
| 错误率阈值 | 超过可自动停止（若配置） |

**关联接口用例**

- 添加多个 **API 用例**，设置 **权重** 或 **固定比例**（如 1:2 严格轮询）
- 可配置单接口请求间隔（ms）
- 支持 **CSV 参数化**（轮询、独占等策略）

### 执行场景

1. 在场景列表点击 **执行**
2. 选择 **执行环境**
3. 若已部署 Worker，可勾选 **使用分布式 Worker**
4. 执行完成后到 **执行记录** 查看

## 执行机（Worker）

**路径**：**性能测试 → 执行机**

### 启动命令（示例）

```bash
cd runner
python perf_worker.py --master http://后端地址:8000 \
  --token my-local-token \
  --name "压测机-01" \
  --max-concurrent 200 \
  --project-id 当前项目ID
```

- `--project-id` 须与顶部所选 **项目 ID** 一致，否则列表不显示或无法分配任务
- 启动后本页显示 **在线/空闲/执行中**、心跳时间

### 何时需要 Worker

- 单机并发不足或需多机叠加 QPS 时使用
- 小规模验证可在场景执行时不勾选分布式（由平台侧发起）

## 执行记录

**路径**：**性能测试 → 执行记录**

| 指标 | 说明 |
|------|------|
| QPS | 每秒请求数 |
| 响应时间 | 平均、分位（P90/P95 等，以页面为准） |
| 错误率 | 失败请求占比 |
| 趋势曲线 | 秒级变化 |

支持 **多轮执行结果对比**，用于发版前后对比。

### 报告导出与邮件

- 报告页可 **导出 HTML** 或 **发送报告邮件**（需配置 **系统管理 → SMTP** 与 **项目通知配置** 邮件收件人）
- 通知配置中开启 **「性能测试执行完成后自动发送报告」** 后，压测结束（成功/失败/停止）会自动推送 HTML 附件
- 推送记录可在 **系统管理 → 推送记录** 查看

## 定时压测

**路径**：**性能测试 → 定时压测**

| 字段 | 说明 |
|------|------|
| 任务名称 | 标识 |
| 关联场景 | 要执行的场景 |
| 执行环境 | 目标环境 |
| 执行类型 | 间隔（≥60s）/ 固定时间 / Cron（如 `0 2 * * *` 每天 2 点） |
| 启用 | 开关 |

## 使用建议

- 压测前在 **低并发** 下验证脚本与数据正确
- 与被测方确认窗口，避免影响生产
- 结合 **首页看板** 性能域筛选查看历史趋势
- CSV 数据注意脱敏，勿将生产真实隐私写入仓库

## 常见问题

**Q：Worker 显示离线？**  
检查 `--master` 地址、网络、token；`project-id` 是否匹配。

**Q：QPS 很低？**  
提高并发或增加 Worker 节点；检查被测服务瓶颈与网络。

**Q：错误率 100%？**  
先用 **接口用例** 单跑确认；检查 Host、Token、压测数据是否有效。
