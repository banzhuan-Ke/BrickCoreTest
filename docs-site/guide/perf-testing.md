# 性能测试

## 适用场景

对 HTTP 接口进行压力测试：吞吐量、响应时间分位、错误率；支持多接口混合场景、梯度加压、分布式 Worker。

## 使用前准备

| 项 | 说明 |
|----|------|
| 项目与环境 | 已配置，Host 指向压测目标（**勿对生产误压**） |
| 接口用例 | 在 **接口自动化 → 用例管理** 中维护被压接口 |
| 执行机（可选） | 分布式压测需注册 Worker（**推荐 BrickCoreRunner 客户端**） |

## 基本流程

```
场景管理 →（启动执行机）→ 执行压测 → 执行记录 / 报告对比
         ↘ 定时压测（可选）
```

## 场景管理

**路径**：**性能测试 → 场景管理**

### 压测模式

| 模式 | 说明 |
|------|------|
| **固定模式** | 固定并发 + 持续时长（秒） |
| **循环模式** | 固定并发 + 每用户循环次数 |
| **梯度模式** | 多阶段递增并发与时长 |
| **流式阶段** | 每虚拟用户 **1 次** SSE 流式请求，采集问答各阶段耗时（需用例支持 SSE） |
| **业务链路** | 多 API 步骤顺序执行，步骤间 extractors 传参（登录→业务接口等） |

固定/循环/梯度模式还可勾选 **流式问答**：在持续压测中对指定用例走 SSE 引擎。

**流式 / 链路专属配置**

| 参数 | 说明 |
|------|------|
| `stream_profile.parser_id` | 流式解析器（默认 `qa_sse_v1`） |
| `stream_profile.timeout_seconds` | SSE 读空闲超时（默认 600s，非整段回答上限） |
| `request_detail_level` | 执行时选择 **简略** / **详细**（详细模式额外保留成功请求 HTTP trace，不影响 QPS/RT） |
| 链路步骤 | 每步可选是否走流式；阶段 sync 在本机/单 Worker 内同步 |

| 参数 | 说明 |
|------|------|
| 并发用户数 | 1～1000（视环境与 Worker 能力） |
| Ramp-up | 爬坡时间（秒），用户逐步启动 |
| 目标 Host | 可覆盖环境 Host |
| 错误率阈值 | 超过可自动停止（若配置） |

**关联接口用例**

- 添加多个 **API 用例**，设置 **权重** 或 **固定比例**（如 1:2 严格轮询）
- 可配置单接口请求间隔（ms）
- 支持 **CSV 参数化**（轮询、独占等策略）
- 用例内可使用 **插入工具** 写入 `${{dt:...}}`；压测执行时与 `${{df:标签}}`、环境变量一并合并

### 执行场景

1. 在场景列表点击 **执行**
2. 选择 **执行环境**
3. 若已注册执行机，勾选 **使用分布式 Worker 执行**
4. 执行完成后到 **执行记录** 查看报告

> **平台本机执行** vs **分布式 Worker**：不勾选 Worker 时由 Docker 内 Backend 发起压测，适合小并发验证；勾选后由执行机本地跑 `perf_worker` 引擎，适合高并发，**压测效果与脚本方式一致**（同一套引擎、同一套场景快照）。

## 执行机（Worker）

压测施压由**在线 Worker**执行（后端不再本机直跑）。**二选一即可**，不必两个都装。

### 方式一：BrickCoreRunner 完整客户端（含 GUI）

1. 安装 **BrickCoreRunner**（见 [执行器说明](./runner-client.md)）
2. 登录平台 → 执行角色选 **仅压测执行机** 或 **UI + 压测**
3. 选择 **压测项目**（须与平台顶部项目一致）→ 点击 **上线**
4. 在 **性能测试 → 执行机** 确认节点 **在线**（来源一般为「完整客户端」）

客户端会在 **当前会话日志** 实时显示压测进度（秒级 QPS、RT、错误率等），完整日志写入 `runner/logs/perf_worker.log`。下线时会自动向平台注销，无需等待心跳超时。

### 方式二：BrickCorePerf 精简压测包（CLI，体积小）

适合服务器常驻或本机只要压测、不要浏览器引擎：

1. 从 **设备管理** 下载 **精简压测包 Win/Mac**，或管理员将 zip 放到 `static/runner/`
2. 解压 → 复制 `.env.example` 为 `.env`，填写 `PERF_MASTER_URL` / `PERF_TOKEN` / `PERF_PROJECT_ID`
3. 运行 `start-perf.bat`（Windows）或 `./start-perf.sh`（macOS）
4. 执行机列表应显示来源「精简包」

说明与冒烟清单见包内 `README-PERF.md`（仓库：`docs/其他文档/README-PERF.md`）。**勿将 Windows 包拷到 Mac 使用。**

### 方式三：命令行源码（开发 / CI）

仍支持在 `runner` 目录手动启动（与上述引擎相同）：

```bash
cd runner
python perf_worker.py --master http://后端地址 \
  --token my-local-token \
  --name "压测机-01" \
  --max-concurrent 200 \
  --project-id 当前项目ID \
  --agent-kind runner_client
```

- `--project-id` 须与顶部 **项目 ID** 一致
- `--master` 与浏览器访问平台地址一致（生产一般不带 `:8000`）
- 脚本方式日志在终端输出，同时写入 `runner/logs/perf_worker.log`

### 对比

| 对比 | BrickCoreRunner | BrickCorePerf | 命令行源码 |
|------|-----------------|---------------|------------|
| 压测引擎 | 同一 `perf_worker.py` | 同左 | 同左 |
| 浏览器 / GUI | 有 | 无 | 无 |
| 报告与指标 | 一致 | 一致 | 一致 |
| 项目 / Token | GUI | `.env` | 手动传参 |
| 典型来源标识 | `runner_client` | `perf_slim` | 自定 / 空=兼容 |

### 何时需要 Worker

- 平台服务器配置较低，或并发较大时
- 多机叠加 QPS
- 小规模验证可不勾选 Worker（Backend 本机压测）

## 执行记录与报告

**路径**：**性能测试 → 执行记录**

| 指标 | 说明 |
|------|------|
| QPS / 成功 QPS | 总吞吐 / 仅成功请求吞吐 |
| 响应时间 | Avg、P90/P95/P99 等（**含失败请求耗时**，错误率单独展示） |
| 接口维度分位 | 每个用例最多保留 **5000** 条 RT 样本（蓄水池采样）；总请求数 / QPS / 错误率不受影响 |
| 错误率 | 失败占比 |
| 趋势曲线 | 秒级 QPS、RT、并发 |

**报告页增强（v1.3.14+ Backend）**

- **SSE 阶段汇总**：问题理解首字、首字时间、思考耗时等（仅统计成功流式请求）
- **流式请求明细**：分页懒加载，支持全部/成功/失败筛选；思考过程、答案预览完整展示
- **HTTP 请求明细**：详细模式下成功 trace + 失败采样；可展开请求头/Body/完整响应
- **导出**：HTML（次要指标与趋势表默认折叠）、流式场景可 **导出 Excel**

支持 **多轮执行结果对比**；可 **发送报告邮件** 或开启完成后自动推送。

## 执行机版本与部署配置

| 配置 | 当前推荐值 | 说明 |
|------|------------|------|
| BrickCoreRunner 客户端 | **≥ 1.3.15** | 与 `runner_client/__init__.py`、`VERSION.txt` 一致 |
| `RUNNER_CLIENT_VERSION_LATEST` | `1.3.15` | 服务器 `.env` / `docker-compose.yml` |
| `RUNNER_ENGINE_VERSION` | `1.0.2` | 与 `runner/settings.py` 中 `RUNNER_VERSION` 一致 |

生产环境浏览器访问平台一般为 **80 端口**（Nginx），`--master` / 客户端服务器地址 **不要写 :8000**（8000 为容器内 Backend）。

## 定时压测

**路径**：**性能测试 → 定时压测**

配置 Cron / 固定时间自动执行场景。任务表单可勾选 **分布式 Worker**（与手动执行一致；无在线 Worker 时自动本机执行）。

## 使用建议

- 压测前在 **低并发** 下验证用例与数据
- 与被测方确认窗口，避免影响生产
- **推荐** 使用 BrickCoreRunner 压测模式，便于选项目、看日志、一键下线
- CSV 数据注意脱敏

## 常见问题

**Q：Worker 显示离线？**  
检查 `--master` / 服务器地址、网络、`project-id` 是否匹配；客户端 v1.3.14+ 下线后应立刻离线。

**Q：客户端看不到压测日志？**  
确认已选压测角色并上线；平台触发压测后查看客户端「当前会话日志」或 `runner/logs/perf_worker.log`（v1.3.14+ 每秒输出 QPS/RT）。

**Q：QPS 很低？**  
提高并发或增加 Worker；检查被测服务瓶颈。

**Q：错误率 100%？**  
先用 **接口用例** 单跑确认 Host、Token、断言。

**Q：和 Locust / 独立 SSE 脚本一样吗？**  
平台基于 **接口用例 + asyncio/httpx 自研引擎**。**流式阶段压测**已内置（`stream_burst` 模式 + `qa_sse_v1` 解析器），无需单独跑 Locust；若仍有外部 Locust 脚本，结果需自行对接。

**Q：报告里响应/思考过程被截断？**  
请使用 **Backend + Worker 最新版**（2026-06 起）并 **重新执行压测**；历史记录的 trace 可能仍为旧版截断数据。完整响应采集不影响 QPS/RT。

**Q：单接口请求很多，P95 和 Locust 差很多？**  
报告 **接口维度** 的 P90/P95/P99 基于 **最多 5000 条** 响应时间样本（蓄水池采样，本机与分布式 Worker 均适用），用于控制内存与存储；**总请求数、QPS、错误率、Min/Max 仍统计全部请求**。全局汇总行的 P95 仍为加权估算。超大规模压测时，分位为近似值，属预期行为；报告页「接口维度详情」上方有说明。
