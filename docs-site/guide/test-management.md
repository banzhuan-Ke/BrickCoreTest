# 测试管理

以**版本交付**为中心，把功能用例、评审、计划运行、缺陷与质量门禁串成一条闭环。自动化资产（Web / App / 接口 / 性能）仍在各自模块维护；本模块负责范围、聚合结果与发布结论。

## 适用场景

| 场景 | 说明 |
|------|------|
| 版本测试范围 | 回答「这次发版测什么」 |
| 用例 / 需求评审 | 设计与可测性确认后再进入计划 |
| 统一计划运行 | 手工 + 多类型自动化在同一批次汇总 |
| 缺陷与追溯 | 失败闭环；需求 → 用例 → 执行 → 缺陷一览 |
| 发布门禁 | 合格快照或授权豁免后进入就绪 / 发布 |

## 入口与菜单

**路径**：左侧 **测试管理**

| 菜单 | 路径 | 说明 |
|------|------|------|
| 版本 | `/test-releases` | 版本列表与详情（范围 / 评审 / 计划 / 缺陷 / 质量） |
| 需求测试中心 | `/ai-testing` | 需求文档 → 测试点 / 方案 / 用例工作台 |
| 功能用例库 | `/ai-functional-cases` | 项目级功能用例资产（可纳入版本） |
| 追溯矩阵 | `/test-traceability` | 覆盖与缺口一览；行内可打开用例、去执行 |
| 评审模板 | `/test-review-templates` | 用例评审检查清单模板 |
| 需求评审 | `/test-requirement-reviews` | 需求可测性评审（从项目需求列表选择） |
| 缺陷台账 | `/test-defects` | 站内缺陷卡片 + 快捷处理 |

> 计划 / 运行详情也可从版本详情 Tab 进入（`/test-plans/{id}`、`/test-plan-runs/{id}`）。

## 推荐主流程

```text
创建版本 → 纳入功能用例（范围）→ 需求/用例评审
  → 从范围创建测试计划 → 运行（手工 / 派发自动化）
  → 失败建缺陷 → 质量预览 / 生成快照（或豁免）
  → 状态变更：测试中 → 就绪 → 已发布 → 归档
```

### 敏捷迭代 · 功能优先（Phase 0–2 / 4）

适合敏捷团队：**先做功能用例与手工测试，自动化有余力再补**。版本概览内置 **敏捷向导**，按步骤完成设计、执行与发布收口。

| 阶段 | 时间 | 步骤 |
|------|------|------|
| **Phase 0 迭代启动** | 0–1 天 | 版本进入测试中 → 关联迭代需求（可从需求测试中心选择）→ 可选需求可测性评审 |
| **Phase 1 功能设计** | 1–3 天 | 维护功能用例 → 纳入测试范围 → 配置风险/负责人 → 发起用例评审 → 评审通过 |
| **Phase 2 功能执行** | 3–8 天 | 建功能计划 → 设环境 → 创建运行 → 必测完成 → 无未关闭 Blocker/Critical |
| **Phase 3 自动化渐进** | 有余力 | 映射资产 → 核心用例映射 → 计划补齐自动化项 → 派发同步（**可选，不阻塞发布**） |
| **Phase 4 发布收口** | 迭代末 | 刷新质量预览 → 生成合格快照（或豁免）→ 就绪 → 发布 |

**快捷入口**

- 版本列表 **新建敏捷迭代**：自动进入「测试中」并打开向导
- 版本概览向导内按钮可直达：需求测试中心、功能用例库、纳入范围、发起评审、创建计划、刷新质量、变更状态等
- 概览 / 质量 Tab 提供 **发布前检查**（必测、缺陷、高风险、快照红绿灯）
- 概览 **自动化渐进** 卡片：未映射核心用例、一键映射、补齐自动化项
- 测试计划 Tab：**一键冒烟 / 一键回归**（可选含自动化）
- 测试范围 Tab：多选后 **批量设置** 风险与负责人
- 创建测试计划时 **含自动化项默认关闭**；有稳定映射后再开启
- **Phase 3 自动化渐进**不阻塞发布，可后续迭代补齐
- 版本详情可 **导出发布包**；关联内部需求（`REQ-*`）全部可测性评审通过后，向导 0.3 自动完成

**指派与通知**：范围负责人、缺陷指派人、用例评审邀请、**计划运行项执行人**、**评审待办**、**质量门禁未通过**等：顶栏铃铛站内信（**SSE 实时推送**）；可在 **项目设置 → 测试通知** 与 **个人中心 → 通知偏好**（免打扰 / 静音事件 / IM @）分别配置；IM（钉钉/企微）可按个人资料手机号 @ 被指派人。铃铛面板可进入 **通知中心**。

与 AI 能力衔接：

1. **AI 测试 → 需求测试中心 / 功能用例库** 产出或维护功能用例  
2. 用例入库后，在版本详情 **纳入用例** 进入本模块范围  
3. 需求侧若启用可测性闸门：未通过需求评审时，部分 AI 生成入口会拦截（手工设计入口如 `create-from-xmind` 按产品约定可不闸门）

## 版本

### 列表

- 按关键词、状态筛选；新建版本需填写版本键、名称等  
- **变更状态** 前会弹出确认：进入 **就绪 / 已发布** 时展示质量门禁摘要（实时结论、陈旧快照、豁免等）  
- **已发布 / 已归档** 不可删除（与后端一致）

### 详情 Tab

| Tab | 能力 |
|-----|------|
| 概览 | 敏捷向导、发布前检查、范围数、需求数、风险分布、自动化覆盖、未关闭缺陷 |
| 需求 | 版本关联外部需求（编号 / 标题 / http(s) 链接） |
| 测试范围 | 纳入功能用例；风险、范围状态、负责人；自动化映射入口 |
| 用例评审 | 发起评审（可选多选评审人）；跳转评审详情 |
| 测试计划 | 从范围创建计划（可含自动化项、指定环境） |
| 缺陷 | 本版本缺陷列表与统计 |
| 质量 | 发布前检查、实时预览、生成快照、批准豁免、报告钻取、历史快照 |
| 智能化 | 运行通过率趋势、自动化稳定度、规则化风险推荐、AI 版本测试总结 |

### 状态机（简要）

| 当前 | 可转到 |
|------|--------|
| 草稿 | 测试中、归档 |
| 测试中 | 就绪、归档 |
| 就绪 | 测试中、已发布、归档 |
| 已发布 | 归档 |
| 归档 | （终态） |

- **进入就绪**：始终硬拦——须有合格质量快照；`pass` 须实时仍通过；或存在**有效豁免**（见下）  
- **发布**：默认**提示模式**（未通过仅警告仍可放行）；环境变量 `TEST_MANAGEMENT_QUALITY_GATE_ENFORCE=true` 后改为硬拦  

## 范围与资产映射

1. 在版本详情 **测试范围** 勾选 / 纳入功能用例库中的用例  
2. 可为范围项设置风险（高 / 严重计入门禁「高风险须有有效结果」）与负责人  
3. 通过 **资产映射**（或功能用例库 / 自动化用例侧入口）关联 UI / App / API / 性能用例  
4. 创建计划时可选择「含自动化项」，从主/回归映射生成计划项  

## 评审

### 用例评审

- 版本详情发起；默认纳入当前版本**全部范围用例**（不受列表筛选影响）  
- 评审人须至少选择一名项目成员（与后端一致）  
- 详情页提交结论：通过 / 需修改 / 拒绝  

### 需求可测性评审

- 菜单 **需求评审**；权限为 `test_review:view` / `submit` / `manage`  
- 未通过时，与可测性相关的 AI 生成路径会提示拦截  

### 评审模板

- 配置检查清单，供用例评审复用  

## 计划与运行

1. 从版本范围 **创建测试计划**，指定类型（回归 / 冒烟等）与执行环境  
2. 进入计划：补齐手工项 / 自动化项；创建运行  
3. 运行中：手工填结果；**派发自动化**（需 `test_plan:run` + 对应模块执行权限）  
4. 打开运行页可 **同步自动化结果**；平台另有定时补偿同步（约 3 分钟）  
5. 失败项可一键建缺陷并带上证据引用  

结果统一为：`not_run` / `passed` / `failed` / `blocked` / `skipped` / `cancelled` / `error` / `unknown` 等（原始模块状态经归一化）。

## 缺陷台账

- 支持按版本下拉、关键词、状态筛选；列表分页；**点行打开右侧全生命周期卡片**  
- 卡片 Tab：基本信息 / 详情与附件 / 关联（运行项·用例·资产·外链）/ 处理记录（评论 + 状态时间线）/ 测试计划  
- 状态按流转规则变更（如 `open → in_progress → resolved → verified → closed`）；支持删除、指派、发现/修复版本与外链  
- 计划运行失败 / 错误 / **阻塞** 可确认后建缺陷并打开同一卡片；版本缺陷 Tab / 质量报告未关闭缺陷可点开  
- 负责人选择项目成员；外链仅允许 `http` / `https`  
- 新建时可关联未发布终态版本；门禁统计「未关闭」不含已修复待验证（`resolved`），列表口径可仍含 `resolved`  
- **图片 / 附件**（参考 MeterSphere）：拖拽上传或粘贴截图；图片缩略图预览，其它文件可下载（依赖 MinIO，`test-defect-files` 桶）  

## 功能用例库（生命周期）

- 功能用例库改为右侧抽屉：基本信息 / 详情步骤 / 需求 / 缺陷 / 测试计划（聚合版本范围、关联缺陷与计划运行）  
- 缺陷 Tab 可跳转缺陷台账卡片（`?defect_id=`）  

## 追溯矩阵

- 可选版本筛选；展示需求 / 测试点 / 功能用例 / 评审 / 自动化 / 最近执行 / 未关缺陷与红黄绿状态  
- 未关缺陷数可跳转缺陷台账；**服务端分页**（关键词 / 状态 / 评审过滤）  
- 版本详情可 **导出发布包**（ZIP：追溯矩阵 CSV + 质量摘要 JSON）  

## 质量门禁

### 预览与快照

1. 打开版本 **质量** Tab → **刷新预览**  
2. 查看实时结论、规则检查项与指标（必测完成、通过率、Blocker/Critical、高风险无结果）  
3. **生成快照** 固化当时结论；若覆盖有效豁免快照会要求确认（`force`）  
4. 界面会对比「实时结论 vs 最近快照」，并标出陈旧 pass、豁免剩余天数  

### 默认规则（可在项目设置配置）

在 **项目设置 → 质量门禁** 调整阈值；预览与快照会使用项目配置。

| 规则 | 默认 | 不满足时 |
|------|------|----------|
| 必测项完成率 | 100% | blocked |
| 必测项通过率 | ≥ 95%（按已完成项） | failed |
| Blocker 未关闭 | 0 | blocked |
| Critical 未关闭 | 0 | failed |
| 高风险范围无有效结果 | 0 | blocked |

### 豁免

- 权限：`test_quality:approve_exception`（默认**项目经理**种子角色；**禁止**版本负责人自批）  
- 填写原因后生成 `conditional_pass` 快照；默认 **14 天**内有效（过期后需重新批准）  
- 过期后质量 Tab 仍显示「重新批准豁免」  

### tip / 强制模式

| 模式 | 环境变量 | 进入就绪 | 发布 |
|------|----------|----------|------|
| 提示（默认） | `TEST_MANAGEMENT_QUALITY_GATE_ENFORCE=false` 或不设 | 硬拦 | 未通过仅警告 |
| 强制 | `=true` | 硬拦 | 未通过且无有效豁免则拦截；陈旧 pass 不放行 |

上线初期建议先用提示模式跑通流程，再开强制。

| 实时推送 | **SSE**（`/sys/inbox/stream`）；连接前须先调 `/sys/inbox/stream-token` 获取 **15 分钟短效 token**（勿把主会话 JWT 放在 URL） |

| 外发渠道 | 复用项目「通知渠道」；各渠道可单独关闭「测试管理指派通知」；**空渠道列表 = 不推送任何外发** |
| IM @ | 钉钉/企微按个人资料手机号 @；飞书机器人在正文展示 @ |
| 合并与补发 | 同实体在 digest 窗口内合并为一条（正文含合并计数）；DND/合并期间未外发的会在 DND 结束或下次通知时 **补发** |

触发事件：`scope_owner_assigned`、`defect_assigned`、`review_invited`、`plan_run_item_assigned`、`review_item_pending`、`quality_gate_failed`。

## 升级注意

1. 执行 `aerich upgrade` 至迁移 **141**（含 **137–140** 站内信/通知偏好/AI 总结、**141** 免打扰时区），重启 Backend，重建前端  
2. **Nginx** 反代须含 `test-management`（仓库 `nginx.conf` / `nginx-docker.conf` 已改）；否则创建接口会 405。Docker：`docker compose up -d --build nginx` 或等价重载  
2. 确认角色具备上表权限  
3. 需要发布硬拦时设置 `TEST_MANAGEMENT_QUALITY_GATE_ENFORCE=true`  

## 常见问题

**Q：进不了就绪？**  
先生成质量快照；若快照是 `pass` 但实时已回退，需重新生成或由授权人豁免。看质量 Tab 的「已陈旧」提示。

**Q：提示模式为何发布仍成功？**  
默认发布只警告不拦截，属预期。要硬拦请开 enforce。

**Q：豁免按钮不见了？**  
需 `approve_exception`；且实时已通过时无需豁免。过期豁免应显示「重新批准豁免」。

**Q：自动化一直不同步？**  
确认运行仍为进行中、项已挂上原始记录 ID；可手动「同步自动化」。认领后长时间无记录会被重置以便重派。

**Q：压测停不下来？**  
计划取消会尝试进程内停止；跨进程 / 重启后的远程 Worker 停止通道仍有限制，可到性能模块查看记录并依赖最大时长结束。

**Q：与设计文档的关系？**  
实施细节与分期见仓库内设计文档；日常操作以本文与版本更新说明为准。
