# Web 自动化

> **录制与回放专题**：测试同学维护用例、排障失败时，请优先阅读 **[Web 录制与稳定回放用户指南](./web-recording-playback.md)** 与 **[Web 失败类型与排障](./web-troubleshooting.md)**。

## 适用场景

Web 界面回归：登录、表单、列表、多步骤业务流程。支持手工编排、Playwright 录制、AI 生成/优化步骤、定时无人值守执行。

## 使用前准备

| 项 | 说明 |
|----|------|
| 项目与环境、测试目录 | 见 **项目与环境**、**测试目录** 章节 |
| 执行器 | Windows **BrickCore 桌面客户端**（设备管理网盘/平台下载） |
| 设备在线 | **Web 自动化 → 设备管理**：可 **网盘/平台下载** 执行器；列表中设备 **在线**；可复制 device_id |

### 设备管理页

- 顶部：**网盘下载** / **平台下载 zip** / 使用说明链接  
- 列表：**客户端版本**、**最后心跳**、复制设备编号  
- 管理员配置网盘：**系统管理 → 执行器发布**

### Windows（推荐）

1. **设备管理** 下载 `BrickCoreRunner.zip` 并解压
2. 运行 `BrickCoreRunner.exe`，使用平台账号登录后点击 **上线**
3. 详见 **执行器使用说明**

### Linux 服务器（引擎源码部署）

若部署环境包含完整 `runner/` 引擎源码，可按 **Linux 无头 Runner** 在服务器无图形界面运行。一般用户请使用 Windows **BrickCoreRunner** 桌面客户端。

### 本机引擎调试（仅含源码的部署环境）

若部署包包含完整引擎源码，可在本机 Python 环境直接启动引擎进行开发调试；日常使用请优先 **BrickCoreRunner** 安装包。

## 基本流程

```
用例管理 → 步骤片段（可选）→ 套件管理 → 执行计划 → 定时任务（可选）→ 执行记录
```

## 用例管理

**路径**：**Web 自动化 → 用例管理**

左侧 **测试目录树** 筛选列表；新建/编辑时通过树形下拉选择 **所属目录**。

### 新建用例

点击 **新建**，填写用例名称、级别、所属目录等，进入步骤编辑器。

### 编排步骤

- 左侧 **关键字面板** 按分组展示步骤类型，拖拽到右侧
- 常用类型：打开页面、点击、输入、断言、等待、条件分支（if / elif / else）、**数据库断言** 等
- 每步可配置定位器、超时、截图等

### AI 生成步骤

点击 **AI 生成步骤**，选择模式：

| 模式 | 适用 | 说明 |
|------|------|------|
| **单页面** | 单页表单、列表 | 抓取 DOM 一次生成步骤；可手动「抓取页面元素」 |
| **多轮探索** | 跨页、需登录跳转 | 执行→再抓→再生成，1～10 轮 |
| **Agent（MCP）** | 复杂探索 | 基于无障碍树逐步规划；**生成后建议入库，勿直接用于定时 CI** |

需填写：起始 URL（Agent/探索必填）、测试描述、可选 AI 模型。

> **部署注意**：Agent / 多轮探索 /「抓取页面」在 **Backend 本机** 启动 Chromium，不经过 Runner。  
> Windows/Linux 源码部署需在 Backend 虚拟环境执行 `python -m playwright install chromium`（见 [Windows 部署](windows-deploy.md)）。  
> 若报 `Executable doesn't exist ... ms-playwright`，按该命令补装并重启 Backend。

### AI 录制步骤

1. 点击 **AI 录制步骤**（录前 checklist 见弹窗提示与 [录制指南 §1.3](./web-recording-playback.md#_1-3-录前-checklist建议每次录制前核对)）
2. 选择 **在线 Runner 设备**、起始 URL
3. 本地弹出浏览器，按业务流程操作
4. 停止录制后 **应用步骤**（默认追加到末尾；也可插入或覆盖全部，见 [录制指南 §2.5](./web-recording-playback.md#_2-5-应用步骤与追加录制)）
5. 编辑页 **交互调试** 试跑（可用调试浏览器底部操作条做拾取 / 高亮 / 验证 / 按步执行），必要时 **AI 优化** 去冗余

完整录制维护流程见 **[Web 录制与稳定回放用户指南](./web-recording-playback.md)**。

### 最近一次执行失败（编辑页）

当该用例 **最近一次执行未通过** 时，编辑页顶部出现红色折叠面板：

| 内容 | 说明 |
|------|------|
| 错误摘要 / 日志 | 来自执行记录，含记录 ID 与时间 |
| 失败步骤高亮 | 步骤列表对失败步红色标注 |
| **AI 根因摘要** | 若该次执行已分析过，内联展示根因与最多 3 条建议 |
| **AI 分析** | 未分析可在此发起；已分析可打开完整抽屉 |

从执行记录 **定位失败** 会带 `?execution_id=` 定位到对应失败上下文。详见 [AI 失败分析](./ai-testing.md#ai-失败分析)。

### 单用例运行

用例列表点击 **运行**：

| 字段 | 说明 |
|------|------|
| 环境 | 必选 |
| 浏览器 | Chrome / Firefox / Safari |
| 界面/无头 | 有界面便于调试，CI 常用无头 |
| AI 定位器自愈 | 步骤失败时尝试 **只换 locator** 并重试（受项目 AI 配置控制） |
| AI Act 兜底 | 自愈仍失败时，按 **业务意图/操作名称** 让 LLM **规划一步** 再执行（**默认关闭**，大改版或探索阶段可开） |
| 设备 | 必选在线 Runner |

> **计划运行**：弹窗无自愈/Act 开关，以 **项目配置 → 项目设置 → 自愈与 AI Act** 中的项目默认为准。

### 步骤编辑：操作名称与业务意图

| 字段 | 说明 |
|------|------|
| **操作名称**（`desc`） | 必填，步骤列表展示，如「点击提交」 |
| **业务意图**（`intent`） | 可选，供 **自愈 / AI Act** 理解「要点哪个元素」；复杂页、相似按钮多时建议填写 |

成功执行的步骤 **不会** 因填写 intent 而调用 LLM；仅在步骤失败进入自愈或 Act 时使用。

### 步骤片段（可复用步骤块）

**路径**：**Web 自动化 → 步骤片段**

将登录、导航等公共流程维护为 **片段**，在用例/套件中 **插入片段** 引用，执行时平台自动展开为片段内步骤。

| 能力 | 说明 |
|------|------|
| 片段库 | 项目级 CRUD，名称、分类标签、版本号 |
| 编辑片段 | 与用例编辑相同：拖拽步骤、**AI 生成**、**AI 录制**、插入子片段 |
| 用例引用 | 用例编辑/新建页点击 **插入片段**，保存为引用节点 |
| 片段变量 | 片段步骤内写 `${{fragment.变量名}}`，引用处点击 **配置** 填入值 |
| 版本提示 | 片段升级后引用块显示「有新版本」，可同步版本号 |
| 执行报告 | 展开后的步骤标注 **片段：xxx** |

**占位符示例**（登录片段）：

- 片段内 URL：`${{fragment.login_url}}`，账号：`${{fragment.username}}`
- 用例引用该片段时，在配置弹窗填入具体值或 `${{环境变量}}`

修改片段内容后，所有引用处 **下次执行自动生效**（无需逐个改用例）。

### 步骤参数与变量

用例/片段编辑区、步骤编辑弹窗提供：

| 按钮 | 作用 |
|------|------|
| **插入变量** | 项目/环境/内置变量；已保存的数据工厂标签 `${{df:标签名}}` |
| **插入工具** | 内联数据工厂工具 `${{dt:...}}`（MD5、加密、随机等，**无需先保存标签**） |
| **数据工厂标签** | 标签选择弹窗（与「插入变量」内标签列表相同） |

**内联示例**：`${{dt:md5|text=@token}}`（引用变量）；`${{dt:md5|text="test@163.com"}}`（固定值用引号，可含 `@`、`|`、`=`）。

UI 套件/计划串行执行时，同一 `dt:` 表达式只计算一次（随机数等同轮一致）。Runner 需包含 `runner/tools/data_tools` 模块（与 Backend 同步）。

### 数据库断言步骤（2026-06）

在 **断言处理** 分组中添加 **「数据库断言」** 步骤，用于 UI 操作后立即校验数据库（如提交订单后查订单状态）：

| 配置项 | 说明 |
|--------|------|
| 数据源 | 数据工厂中已配置的数据源（MySQL / PostgreSQL / Redis） |
| SQL / 命令 | `SELECT ...` 或 Redis `GET key`；支持 `${{变量}}` |
| 操作符 / 期望值 | 与接口库断言相同（equals、exists、row_count_equals 等） |

步骤编辑弹窗顶部可选 **参考环境**，用于加载该环境下的数据源列表。执行时由 Runner 调用平台内部 API 连库，**不**在 Runner 本机直连数据库。

**前置条件**：数据工厂已配置数据源；Runner 配置 `INTERNAL_API_KEY`（与 Backend 一致）。

详见 **数据工厂** 专章 §库断言 → UI 用例步骤。

### input 文件上传与测试文件（2026-06）

Web 步骤 **「input 文件上传」** 需要 Runner 本机存在待上传文件。推荐改用平台 **测试文件**（MinIO），多 Runner 无需各自维护目录。

| 方式 | 适用 | 说明 |
|------|------|------|
| **平台测试文件**（推荐） | 多台 Runner、CI、迁移 | **Web 自动化 → 测试文件** 上传 pdf/xlsx/docx 等；步骤编辑器中选择文件 |
| **Runner 本地 `files_path`**（兼容） | 单机 Runner | 环境配置全局变量 `files_path` 指向本机目录，步骤写 `${{files_path}}/文件名` |

**步骤编辑**：「input 文件上传」步骤顶部为 **测试文件** 下拉/上传；展开 **高级** 可填本地路径。

**测试文件页**：

| 能力 | 说明 |
|------|------|
| 关联引用 | 列表展示被哪些用例/套件/片段引用 |
| 删除保护 | 仍有引用时删除按钮禁用，需先在步骤中解除绑定 |
| 迁移扫描 | **扫描本地路径步骤** 列出仍用 `${{files_path}}` 的步骤，上传同名文件后重新选择 |

执行时 Runner 通过平台预签名 URL 下载文件到临时目录，再交给浏览器上传控件。

### 图像模板定位（Vision，2026-07）

DOM / 自愈 / AI Act 仍搞不定时，可在 **图像定位** 分组使用：

| 步骤 | 说明 |
|------|------|
| 图像模板点击 | 页面截图匹配 MinIO 小图后点击 |
| **图像模板输入** | 匹配输入框区域模板 → 点击聚焦 → 键盘输入（Canvas/自定义控件兜底，v1.4+） |
| 等待图像出现 | 轮询直到模板匹配成功 |
| 断言图像存在 | 断言当前页能匹配到模板 |
| 断言图像不存在 | 断言当前页不能匹配到模板（如弹窗已关） |

步骤编辑可 **上传模板图**（复用元素库 MinIO 存储）。需固定 viewport，分辨率变化会导致匹配失败。

## 套件管理

**路径**：**Web 自动化 → 套件管理**

左侧目录树筛选；表格显示 **所属目录**。

1. **新建套件**，从用例列表勾选加入
2. 拖动调整 **执行顺序**（串行）
3. 配置 **公共前置步骤**（如打开浏览器）；可选 **失败策略**：用例失败时停止后续用例
4. 点击 **运行**：选择环境、浏览器、设备（字段同单用例，含 **自愈 / AI Act** 开关，视项目配置显示）

## 执行计划

**路径**：**Web 自动化 → 执行计划**

左侧目录树筛选。

1. **新建计划**，填写名称、所属目录；可开启 **并行执行**（套件按执行器权重分发）
2. 从右侧 **套件集** 拖拽套件到计划中并排序
3. **运行**：选环境、浏览器、执行器；并行模式下可选 **多个设备 + 权重 + 每设备并发数**（计划运行弹窗 **无** 自愈/Act 开关，以项目默认为准）

| 层级 | 并行说明 |
|------|----------|
| 计划 | 套件可分到多台 Runner，或同一 Runner 多 Browser 并发 |
| 套件内 | 用例仍 **串行**（共用前置浏览器与会话） |

计划是 **定时任务** 的调度对象。

## 定时任务

**路径**：**Web 自动化 → 定时任务**

| 字段 | 说明 |
|------|------|
| 任务名称 | 便于识别 |
| 测试环境 | 执行时使用的环境 |
| 测试计划 | 关联的执行计划 |
| 执行类型 | **间隔执行**（秒，≥60）/ **固定时间** / **Cron 表达式**（分 时 日 月 周） |
| 启用状态 | 关闭后不再触发 |

Cron 示例：`0 8 * * 1-5` 表示工作日 8:00。

首页看板 **待执行定时任务** 区域会展示 48 小时内将触发的任务。

## 执行记录

**路径**：**Web 自动化 → 执行记录**

页顶 **计划 / 套件** Tab 切换查看两类记录（默认计划）；支持按名称、状态、时间筛选。

- 查看计划级或套件级执行状态、耗时、通过率
- 下钻到用例、步骤明细
- 支持 **截图、视频**（若用例开启）
- 失败步骤可使用 **AI 失败分析**
- 步骤若触发 **AI 自愈** 或 **AI Act**，时间轴会展示原/新定位或 Act 详情，可 **写回用例** 固化（需 `ui_case:edit`）
- 套件报告底部 **「执行环境配置」** 展示本次 `env_payload`（含 `browser`、`headless` 与 **`variables` 共享变量池**）；其中的 API Key、禅道等字段来自 **项目/环境 global_vars**，不是接口套件数据混入

用例/套件列表也可查看单次运行记录。

## 使用建议

- 定位优先 **角色、文本、data-testid**，减少纯 XPath 依赖
- 长流程拆多个用例，再放入同一套件
- Agent 模式适合摸底，正式回归用录制或手工稳定步骤
- 页面小改可依赖 **定位器自愈**；Heal 仍失败且已开启 **AI Act** 时可再兜底一步
- 大改版后建议在报告中 **写回自愈/Act 定位** 或人工改步骤，避免每次执行都消耗 Token

## 批量执行 vs 测试计划

| 维度 | 临时 / 单套件跑 | 测试计划 + 定时任务 |
|------|-----------------|---------------------|
| 适用 | 开发自测、改步后验证 | nightly、发布回归 |
| 组织 | 选手动套件或用例 | 计划编排多套件，可 **并行** 多 Runner |
| 报告 | 套件或用例级 | 计划级汇总与历史 |
| 命名 | `临时-{模块}-{日期}` | `回归-{产品}-{环境}` |

详见 [录制指南 §5.4](./web-recording-playback.md#_5-4-批量执行-vs-测试计划)。

## 常见问题

**Q：录制维护、失败怎么排？**  
见 **[Web 失败类型与排障](./web-troubleshooting.md)**。

**Q：录制按钮灰了？**  
无在线 Runner，先通过 **执行器客户端上线**（勿重复启动多个 `main.py`），并刷新设备管理。

**Q：同配置两个套件一个过一个挂？**  
见 [Runner 排查指南](./runner-troubleshooting.md)（多为多进程抢 MQ 或缺 `jsonpath_ng`）。

**Q：步骤执行超时？**  
调大该步超时；检查环境 Host 与网络。

**Q：定时任务没跑？**  
确认任务已启用、计划与环境下拉正确；看 **首页看板** 待执行列表。

**Q：与接口测试的关系？**  
UI 与接口独立模块；**环境变量池共用**（项目/环境 global_vars），故 UI 报告 env 中可能出现接口相关变量名。登录态若走 HTTP 接口，可在 **接口自动化 → Token 授权** 维护。

### 免登录 / 会话保持（可选）

不想每次回放都跑登录 UI 时：

1. **环境 → 编辑 →「Web 启动登录态注入」**：配置 `Authorization`、LocalStorage、Cookie，或填执行机上的 `storage_state` 路径。
2. **用例步骤**：`设置鉴权Token` / `设置LocalStorage` / `设置SessionStorage` / `设置Cookie`（Storage 类须先 `访问页面url` 打开目标域）。
3. **导出复用**：登录成功并进入业务页后用「导出登录态」生成文件，再把路径填回环境启动注入。

「导出登录态」除 Cookie / LocalStorage 外，会附加 **`sessionStorageOrigins`**（当前页 Session Storage），注入时按 origin 写回。须使用支持该能力的执行器；会话过期后需重新导出。

仍可用 **步骤片段** 做完整登录流；平台不破解验证码/SSO。

#### 免登录通用配法（设置鉴权Token）

1. 环境变量准备 `TOKEN`（登录接口或抓包拿到的凭证）。
2. 步骤：
   - 打开浏览器 → 访问目标域（要写 LocalStorage 时必须先打开同域）
   - **设置鉴权Token**：
     - `token=${{TOKEN}}`
     - 请求头名默认 `Authorization`，前缀默认 `Bearer`（按目标站改）
     - LocalStorage 键：**可选**；目标站把纯 token 存在某键时再填（写入**字符串**）
   - 再打开业务页（不要刻意停在登录页）
3. 更通用：登录一次后用「导出登录态」，环境里配 `storage_state` 路径。
4. 若目标站 LocalStorage 需要 **JSON 整包**（少见），用「设置LocalStorage」自己填 JSON，不要指望鉴权Token 步骤拼业务结构。
