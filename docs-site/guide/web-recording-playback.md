# Web 录制与稳定回放用户指南

> 面向测试同学的 **录制 → 编辑 → 交互调试 → 计划执行 → 排障** 完整手册。  
> 失败分类与决策树见专章：[Web 失败类型与排障](./web-troubleshooting.md)。

## 平台特点概览

| 维度 | 说明 |
|------|------|
| 执行 | **私有化 Runner**（本机/内网 Windows） |
| 能力范围 | Web + App + API + 性能 + AI **一体** |
| 调试 | **交互调试**：编辑页选步骤试跑、调试到此步 |
| 定位 | 多候选 + **定位器自愈** + 可选 AI Act |
| 数据 | **步骤片段**、数据工厂、环境变量 |

---

## 1. 快速开始

### 1.1 前置条件

| 项 | 说明 |
|----|------|
| 项目与环境 | 已创建项目、测试环境（含 Host / 全局变量） |
| Runner 在线 | **Web 自动化 → 设备管理** 中设备状态为 **在线** |
| 客户端 | Windows **BrickCoreRunner.exe** 登录并 **上线**（见 [执行器使用说明](./runner-client.md)） |

### 1.2 录制第一个用例（5 步）

```
设备管理确认 Runner 在线
    → 用例管理 → 新建 / 编辑用例
    → 点击「AI 录制步骤」
    → 选择设备 + 起始 URL → 开始录制 → 在弹出浏览器中操作
    → 停止录制 → 应用步骤 → 编辑页「交互调试」试跑 → 保存
```

### 1.3 录前 checklist（建议每次录制前核对）

- [ ] Runner **在线**，客户端版本 ≥ 平台要求（设备管理可查看）
- [ ] 起始 URL 可访问（内网/VPN 已连通）
- [ ] 录制窗口 **最大化或固定分辨率**（图像定位、截图断言依赖 viewport）
- [ ] 复杂登录：先在浏览器 **手动完成登录** 再录业务步骤，或将登录维护为 **步骤片段**
- [ ] 下拉/悬浮菜单：录制配置中 **悬浮停留时间** 足够（默认 1～2 秒）
- [ ] 录完后 **不要直接进定时 CI**：先交互调试或单用例跑通
- [ ] 应用步骤默认 **追加或插入**；选「覆盖全部」会替换编辑器内步骤，录完后用 **交互调试** 试跑

> 录制弹窗内也有相同 checklist 摘要提示。

## 2. 录制测试

**入口**：用例编辑页 / 步骤片段编辑页 → **AI 录制步骤**。

### 2.1 支持的操作

| 类型 | 说明 |
|------|------|
| 点击 / 双击 | 按钮、链接、菜单项 |
| 输入 / 清空 | input、textarea（password 字段建议录后用环境变量替换） |
| 选择 | select、radio、checkbox |
| 键盘 | Enter、Tab 等 |
| 导航 | 地址栏跳转、前进后退（会生成打开页面或点击步骤） |
| 悬浮 | 下拉、级联菜单（需配置停留时间） |
| iframe | **同源 iframe** 内操作会自动加 iframe 前缀 |

### 2.2 录制建议

1. **操作节奏**：每步操作后稍等页面稳定（SPA 加载完成再点下一步）
2. **一步一事**：一次录制聚焦一条业务路径，长流程拆多个用例 + 步骤片段
3. **命名清晰**：应用步骤后检查每步 **操作名称**（`desc`），复杂按钮补 **业务意图**（`intent`）供自愈/AI Act 使用
4. **少录冗余**：不必录「点空白关闭弹窗」 unless 业务需要；可用 **AI 优化** 精简，优化后务必 **交互调试试跑**
5. **密码**：勿将生产密码写入步骤明文；用 **环境变量** `${{password}}` 或后续规划的步骤级脱敏

### 2.3 下拉框 / 悬浮菜单

- 录制前在弹窗调 **悬浮停留时间**（500ms～5s）
- 若菜单项未录上：加长停留时间后 **重录该段**，或编辑页手补 click 步骤
- 执行失败且为 dropdown：优先检查 locator 是否落到 **全局 nth**；可手改定位或开 **定位器自愈**

### 2.4 iframe

- 仅 **同源** iframe 自动识别；跨域 iframe 无法注入录制脚本
- 步骤中会带 `iframe` 前缀，编辑页 LocatorSelector 可切换 frame 上下文

### 2.5 应用步骤与追加录制

停止录制后，在弹窗选择 **应用方式**：

| 方式 | 说明 |
|------|------|
| **追加到末尾** | 保留已有步骤，新步骤接在后面（默认推荐） |
| **插入到当前步之后** | 在步骤条选中某步后录制，新步骤插入其后 |
| **覆盖全部** | 替换编辑器内全部步骤，适合全新重录 |

用例编辑页步骤行还支持 **从这里开始录制**：自动回放前置步骤后在同一会话接录，适合登录后补录业务段。

### 2.6 录制 FAQ

| 问题 | 处理 |
|------|------|
| 录制按钮不可用 | 无在线 Runner → 客户端上线并刷新设备管理 |
| 浏览器未弹出 | 检查 Runner 日志；是否被防火墙/杀软拦截 Chromium |
| 录到的步骤很少 | 是否未在 **录制中** 状态就关了浏览器；是否操作过快 |
| 定位质量「风险」 | 录制结果表查看说明；编辑页改 locator 或加 `data-testid` 后重录 |
| 应用后步骤被清空 | 是否选了 **覆盖全部**；默认追加/插入会保留已有步骤 |

更多 Runner 侧问题见 [Runner 排查指南](./runner-troubleshooting.md) §Web 录制。

## 3. 步骤维护

录完 **应用步骤** 后，在 **用例编辑页** 维护（不在录制弹窗内做正式调试）。

### 3.1 LocatorSelector（多候选定位）

录制会为每步生成 **多个候选定位器**，编辑步骤时可在 LocatorSelector 中切换：

| 优先级（默认） | 类型 | 说明 |
|----------------|------|------|
| 高 | `data-testid` / role / placeholder | 抗 DOM 变更，**推荐** |
| 中 | 区域链式、文本、class | 业务区域 + 文案 |
| 低（备选） | CSS 结构路径、XPath | 回放顺但 DOM 一改易挂；稳定后台可选用 |

**改哪个字段、修什么问题**：

| 现象 | 建议修改 |
|------|----------|
| 元素找不到 | 换候选 locator；或 **AI 自愈** / 手调 |
| 点错元素 | 缩小 scope（父级区域 + 子定位）；补 **intent** |
| 页面小改就挂 | 让研发加 `data-testid`（见 §7 可测性建议） |
| 下拉 option 超时 | 限定下拉容器；避免 `nth(10)` 类全局匹配 |

### 3.2 步骤片段

登录、导航等公共流程维护为 **步骤片段**，用例中 **插入片段** 引用；片段升级后用例 **自动生效**。详见 [Web 自动化](./ui-automation.md) §步骤片段。

### 3.3 AI 优化（录制后可选）

- 合并冗余跳转/等待、补断言、润色操作名称
- **不会修改 locator**（v1.3.6+）
- 优化可能去掉多余 click；拿不准时 **对照原步骤** 或 **交互调试试跑**

## 4. 交互调试

**路径**：用例编辑页 → **交互调试** 面板（与录制弹窗分离）。

调试会话就绪后，Runner 会打开 **有头浏览器**：你可以在页面上手动就位，用编辑页按钮试跑，也可以使用浏览器底部的 **调试操作条**（无需来回切窗口找所有能力）。

### 4.1 主要能力

| 能力 | 说明 |
|------|------|
| 打开浏览器 / 手动就位 | 选择环境、浏览器与在线 Web Runner；打开后不自动跑业务步骤，请先操作到目标页面状态 |
| 选中步骤 | 在步骤列表点击卡片即可选中（排序请用左侧 **拖拽手柄**）；选中步与操作条「步骤 N」同步 |
| 执行本步 / 执行至末尾 | 编辑页调试条或浏览器操作条均可；也可用步骤行「执行本步」「调试到此步」 |
| 从中间步接录 | 在交互调试会话中可「从这里开始录制」，接录新步骤 |
| 高亮 / 取消高亮 / 验证 | 按当前步骤定位器在页面上高亮元素、清除高亮，或验证是否匹配到可见元素 |
| 拾取元素 | 在调试浏览器中点击目标元素；编辑页弹出回填对话框，可 **替换某步定位器** 或 **插入新步骤** |
| 步骤同步 | 编辑器改步骤后若提示不一致，请先 **同步最新步骤** 再执行 |
| 与录制边界 | 调试 **不产出步骤**；新流程步骤仍用 **AI 录制** 或接录 |

### 4.2 调试浏览器操作条

会话 **就绪** 后，调试浏览器底部提供快捷按钮（与编辑页能力对应）：

| 按钮 | 作用 |
|------|------|
| 拾取 | 开启/关闭拾取；拾取成功后到编辑页完成回填 |
| 高亮 | 高亮当前选中步骤的定位器 |
| 取消高亮 | 清除页面上的高亮 |
| 验证 | 验证当前步骤定位器 |
| 执行本步 | 仅执行选中步 |
| 执行至末尾 | 从选中步连续执行到用例末尾 |

**说明**：

- 请先选中 **含定位器** 的步骤（点击、输入、断言元素等）；「强制等待」「打开网页」等无定位器步骤不支持高亮/验证，属正常表现。
- 高亮、验证等结果会在编辑页交互调试区域提示；执行过程可在「最近执行明细」与步骤状态中查看。
- 同一 Runner 上，交互调试与 AI 录制、计划/套件执行互斥：若提示设备占用，请先关闭调试浏览器或结束其他任务。

### 4.3 推荐流程

`录制 → 应用 → 交互调试修正（操作条 / 编辑页）→ 单用例运行 → 入套件/计划`

BrickCore 支持 **从中间步调试** 与 **从步骤接录**；录完维护、失败排障均建议在编辑页配合交互调试完成。

详细按钮说明亦可对照平台 **操作手册** 中「交互调试」章节。

## 5. 回放与执行

### 5.1 执行层级

```
单用例运行（调试用）
    → 套件管理（串行多用例，共享浏览器会话）
        → 执行计划（多套件；可并行分到多台 Runner）
            → 定时任务（无人值守）
```

### 5.2 单用例 / 套件运行参数

| 字段 | 说明 |
|------|------|
| 环境 | 必选；注入 Host、global_vars |
| 浏览器 | Chrome / Firefox / Safari |
| 有界面 / 无头 | 调试选有界面；定时 CI 常用无头 |
| 设备 | 必选在线 Runner |
| AI 定位器自愈 | 失败时自动换候选 locator 并重试 |
| AI Act 兜底 | 自愈仍失败时 LLM 规划一步（**默认关**，耗时长） |

> **计划运行**：弹窗无自愈/Act 开关，以 **项目配置 → 项目设置 → 自愈与 AI Act** 项目默认为准。

### 5.3 执行前检查

- [ ] 环境 Host、账号变量正确
- [ ] Runner 在线且未被其他任务占满
- [ ] 用例已在编辑页或交互调试 **跑通至少一次**
- [ ] 定时任务关联的计划、环境、Cron 正确

### 5.4 批量执行 vs 测试计划

| 维度 | 批量 / 临时跑 | 测试计划 + 定时任务 |
|------|---------------|---------------------|
| 适用 | 开发自测、临时回归 |  nightly、发布前门禁 |
| 组织 | 选手动套件或用例 | 计划编排多套件，可并行 |
| 报告 | 套件级 / 用例级 | 计划级汇总 + 历史对比 |
| 命名建议 | `临时-{模块}-{日期}` | `回归-{产品}-{环境}`、`冒烟-{版本}` |
| 推荐 | 调试阶段 | 稳定后纳入计划 + Cron |

## 6. 结果与排障

执行记录在 **Web 自动化 → 执行记录**；失败处理详见 **[Web 失败类型与排障](./web-troubleshooting.md)**。

简要流程：

```
看报告失败步 → 截图/日志
    → 判断：改步骤 vs 提缺陷 vs 环境/数据问题
    → 编辑页交互调试 / 改 locator / 写回自愈
    → 单用例重跑 → 再进套件/计划
```

| 入口 | 说明 |
|------|------|
| AI 失败分析 | 报告页 / 用例编辑页失败面板；默认识图关闭，需时手动开启「截图识图」 |
| 定位器自愈写回 | 报告时间轴「写回用例」固化新 locator |
| AI Act 写回 | Act 成功后可写回定位 params |

## 7. AI 辅助

### 7.1 定位器自愈（Heal）

- **时机**：步骤执行报错且项目开启自愈
- **行为**：LLM 根据页面 snapshot + **intent** 换 locator，自动重试
- **建议**：复杂页、相似按钮多步填写 **业务意图**；CI 可默认开启

### 7.2 AI Act 兜底

- **时机**：Heal 仍失败且开启 Act
- **行为**：按 intent/操作名规划 **一步** 再执行
- **注意**：**耗时长**（Heal → 重试 → Act → 再试）；大改版后应 **写回用例** 或人工改步，避免每轮消耗 Token
- **与智能步骤的区别**：Act 是失败兜底；**智能步骤**为用例内自然语言步骤类型，执行时由 AI 主动规划操作

### 7.3 AI 生成步骤 vs 录制 vs 智能浏览器

| 方式 | 产出 | 适用 |
|------|------|------|
| **AI 录制** | 可回归 click/fill 步骤 | 熟悉页面、稳定回归 **首选** |
| **AI 生成** | 一次性生成步骤草稿 | 新页面摸底 |
| **Agent / 智能浏览器** | 探索型步骤 | 演示/探路，**勿直接上定时 CI** |

### 7.4 断言边界

- 录制 **不会** 自动生成业务断言；可用 **AI 优化** 按描述补断言
- 否定断言（元素不存在/不可见）需在优化描述中写明预期

## 8. 附录：可测性建议（给研发）

为降低 UI 自动化维护成本，请业务前端在关键控件上：

| 建议 | 示例 |
|------|------|
| 稳定测试 ID | `data-testid="order-submit-btn"` |
| 按钮可访问名称 | `<button aria-label="提交订单">` |
| 表单 label 关联 | `<label for="mobile">` + `id="mobile"` |
| 下拉区分 | 同类下拉不同 `data-testid` 或父级区域 |
| 避免动态 id | 少用手写 `id="el-id-3847"` 作为唯一定位 |
| 列表行 | 行内操作加 testid 或稳定文案 |

测试侧可在迭代评审时转发本表；录制前优先使用已有 testid 的页面。
