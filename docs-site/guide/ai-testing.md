# AI 测试

## 适用场景

大模型辅助测试设计：需求→功能用例、测试点/方案、失败根因分析、UI/API 步骤生成、禅道互通。

## 使用前准备

| 项 | 说明 |
|----|------|
| AI 模型配置 | 管理员在 **系统管理 → 平台配置 → AI** 配置 API Key、模型名 |
| Vision 模型 | 需求含流程图/原型图时必须配置 |
| 项目 | 顶部已选择目标项目 |

## AI 工作台

**路径**：**AI 测试 → AI 工作台**

建议作为 AI 工作 **起点**，集中展示：

- 需求、测试点、用例数量与 **转化漏斗**
- 进行中的 **批量生成任务** 与进度
- **待办提醒**（如待审核用例、失败待分析）
- 最近需求、最近 AI 记录、最近失败（可一键分析）
- 快捷跳转到各 AI 子功能（含 **需求测试中心**）

## 需求测试中心

**路径**：**AI 测试 → 需求测试中心**（`/ai-testing`）

原「需求用例生成」与「测试分析」已合并为本入口，按需求完成文档解析、测试设计、用例生成与导出。

|------|------|------|
| 需求列表 | `/ai-testing` | 上传文档、查看统计、进入工作台 |
| 全部测试点 | `/ai-testing/test-points` | 项目级测试点检索 |
| 全部测试方案 | `/ai-testing/schemes` | 项目级方案列表 |
| 单需求工作台 | `/ai-testing/requirements/{id}` | 统一 Tab 工作区 |

### 工作台 Tab

| Tab | 能力 |
|-----|------|
| 概览 | 统计卡片、快捷跳转 |
| 需求文档 | 章节树、AI 生成用例、批量任务 |
| 思维导图 | 测试点可视化、生成测试点 |
| 测试点 | 列表筛选、确认、**导入 XMind**、从测试点生成用例 |
| 测试方案 | 生成方案、导出 Word |
| 功能用例 | 编辑、导出禅道、复制到功能用例库 |

**分享链接示例**：`/ai-testing/requirements/10?tab=points`

> 旧路径 `/ai-requirements`、`/ai-test-analysis` 会自动重定向到工作台。

### 上传文档

支持：**PDF、Word（.docx）、TXT、Markdown**。

含图片的文档需配置 **Vision 模型** 用于文档理解。

Word 文档的章节树依赖 **标题样式**（Heading 1/2/3 或「标题 1/2/3」）。钉钉文档、WPS、部分在线协作工具导出的 `.docx` 会使用内部 styleId（如 `2`、`3`、`4`），平台会自动读取 `styles.xml` 映射为标题；若上传后只显示一个「正文」节点，请在 Word 中重新应用标题样式，或导出为 PDF / Markdown（`#` 标题）后上传。

上传后可在 Tab「需求文档」点击 **重新解析**，无需重新上传文件。

### 生成流程（文档 → 用例）

1. 在需求列表 **上传** 需求文件，进入 **工作台**
2. Tab「需求文档」：左侧 **章节树** 勾选范围（见下节「生成范围与章节覆盖」）
3. 选择 **文档理解模型**（含图时）与 **用例生成模型**
4. 配置批次（名称、条数等），点击 **生成**；大文档建议 **加入队列** 后批量生成
5. 大文档走 **异步批量**，进度在 AI 工作台查看
6. Tab「功能用例」：**编辑、删除、调整** 生成结果
7. **导出禅道 XLSX** 或 **复制到功能用例库**

### 生成范围与章节覆盖

Tab「需求文档」左侧 **生成范围** 区提供章节树与快捷操作：

| 操作 | 说明 |
|------|------|
| 全选 | 勾选文档全部章节（默认打开文档时即为全选） |
| 清空 | 取消所有勾选 |
| **选未覆盖** | 根据已有用例的 `section_ids`，**仅勾选尚无对应用例的章节**，便于补生成缺口 |
| 重新解析 | 按已上传原文件重新切分章节，无需重新上传 |

勾选后下方显示：**已选章节数 · 约多少字 · 几张图 · 预估输入 Token**。范围过大时顶部会出现黄色/红色提示，建议缩小勾选。

**章节覆盖检查**（生成范围下方）：

- 展示文档总节数、**已有用例覆盖**节数、**未覆盖**节数
- 可展开查看未覆盖章节列表
- 右侧 **生成队列** 有待执行批次时，会显示「队列执行后预计覆盖」节数

**推荐用法**：

1. **首轮**：按业务场景（如「场景一」「场景二」）分别勾选 → **将当前勾选加入队列** → **批量生成**
2. **补缺口**：点击 **选未覆盖** → 确认未覆盖列表 → 入队 → 对该批点 **补充**（批次名须与首次一致）
3. **Token 拦截**：预估为 block 时，请减少单次勾选章节或拆成多批队列

### 测试分析流程（测试点 → 方案 → 用例）

1. Tab「思维导图 / 测试点」：勾选章节 → AI **生成测试点**，或 **导入 XMind**
2. 筛选、**确认** 测试点（主/子模块为精确匹配）
3. Tab「测试方案」：基于测试点生成方案，可导出 Word
4. Tab「测试点」：按当前筛选/勾选 → **从测试点生成功能用例**（单次最多 50 条）
5. Tab「功能用例」确认后 **复制到功能用例库**

### 项目级规范

在工作台 Tab「配置」或 **平台配置 → AI** 中维护禅道字段映射、用例标题模板（支持变量说明与预览）。

## 功能用例库

**路径**：**AI 测试 → 功能用例库**

### 列表与筛选

按标题、模块、禅道 ID、优先级、来源、导入批次等筛选排序。来源为某需求时，可点击 **需求** 跳回需求测试中心工作台。

### 常用操作

| 操作 | 说明 |
|------|------|
| 新建 / 编辑 | 手工维护用例 |
| 禅道 XLSX 导入 / 导出 | 与禅道流程互通（半成品 XLSX 建议在此导入） |
| 重复检验 | 按标题+模块（或含步骤摘要严格模式）找重复 |
| 回滚本批 | 按导入批次撤销 |
| AI 生成 UI | 批量将用例转为 UI 步骤预览后导入 |
| 录制生成 UI | 单条用例通过录制生成 UI 草稿 |

### 转 Web 自动化

选用例 → **AI 生成 UI** 或 **录制生成 UI** → 在 **Web 自动化 → 用例管理** 中继续完善步骤与断言。

状态：未生成 / 生成中 / 已生成 / 已导入。

## AI 模型配置

**路径**：**系统管理 → 平台配置 → AI**（通常管理员）

### LLM 模型

| 字段 | 说明 |
|------|------|
| 供应商 | OpenAI、DeepSeek、通义、Claude、自定义等 |
| API Key / Base URL | 按供应商填写 |
| 模型名 | 如 `gpt-4o`、`deepseek-chat` |
| 温度、最大 Token、超时 | 影响生成质量与耗时 |
| 默认 / 启用 | 多条配置时指定默认 |

支持 **测试连接** 验证 Key 有效。

### 执行与自愈

**路径**：**项目配置 → 项目设置 → 执行与自愈**（按当前顶栏项目生效；软区间等「功能用例生成」策略也在此页）

**API**：`GET/PUT /sys/project-settings/execution?project_id=`（旧路径 `/ai/configs/execution-settings` 仍兼容）

| 配置项 | 说明 |
|--------|------|
| **定位器自愈总开关** | 关闭后 Runner 不自动 Heal |
| **执行默认开启自愈** | 未在弹窗覆盖时的默认值（通常 **开启**） |
| **允许运行弹窗覆盖自愈** | 关闭后用例/套件运行弹窗不显示自愈开关 |
| **AI Act 总开关** | 关闭后 Runner 不执行 Act 兜底（**默认关闭**） |
| **执行默认开启 AI Act** | 未在弹窗覆盖时的默认值 |
| **允许运行弹窗覆盖 AI Act** | 关闭后运行弹窗不显示 Act 开关 |
| **单用例 AI Act 上限** | 防止单用例 Token 失控（默认 3，可配 1～10） |
| **默认 AI 自定条数** | 打开需求生成页时是否默认勾选「AI 自定条数」 |
| **绝对下限 / 上限** | AI 自定模式下条数软区间的硬夹取范围 |
| **软上/下限系数** | `soft_min/max ≈ 建议条数 × 系数`，再与绝对上下限夹取 |
| **参考条数硬上限** | 「参考条数」模式下输入框允许的最大值 |

**执行链路**：步骤失败 →（可选）**Heal 换 locator 重试** → 仍失败 →（可选）**AI Act 规划一步** → 仍失败则步骤失败。

**场景绑定**：`locator_heal`（自愈）、`ai_act`（Act 兜底）；可在 **场景绑定** Tab 指定模型。

> Runner `.env` 的 `AI_HEAL_ENABLED` / `AI_ACT_ENABLED` 仅作 **运维熔断**；产品策略以上述项目配置为准。Backend 派发时写入 `ai_heal_enabled`、`ai_act_enabled` 等字段，Runner 只读 payload。

### 场景绑定

## AI 失败分析

执行失败后，将步骤、日志、断言与（可选）截图交给 LLM，输出根因、可能原因与修复建议。

### 入口

| 位置 | 说明 |
|------|------|
| **执行记录 / 报告页** | 失败行「AI 分析」打开侧栏抽屉 |
| **用例编辑页** | 最近一次执行失败时，顶部红色折叠面板内联展示已缓存分析，并可打开完整抽屉 |
| **AI 工作台** | 「最近失败 · AI 分析」快捷入口 |
| **批量** | 报告页「批量 AI 分析失败」（Top N，默认识图关闭） |

**前置**：项目已开启失败分析（**项目配置 → 项目设置 → 执行与自愈**）；执行人具备 `ai_test:execute`。单次运行可在弹窗勾选「失败分析」以控制报告页是否展示分析入口。

### UI/App 识图模式

| 模式 | 说明 |
|------|------|
| **纯文本**（默认） | 仅分析步骤、日志与错误信息，**不传截图**，费用较低 |
| **截图识图** | 分析前手动开启「截图识图」，并可选 Vision 模型（如 qwen-vl）；适合元素不可见、布局异常类问题 |

识图不会自动开启；未配置 Vision 模型或调用失败时会降级为纯文本分析。

### 缓存与重新分析

- 分析结果写入 `ai_generate_record`，**再次打开优先展示历史结果**
- 侧栏点击 **「重新分析」** 并传 `force_refresh` 才重新调用 LLM

### 输出字段

根因总结、可能原因列表、修复建议、错误分类、置信度；UI 识图成功时标记 `vision_used`。

## 使用建议

- 所有 AI 生成结果 **人工审核** 后再纳入正式回归
- 含图需求务必配 **Vision**
- 测试点超过 50 条时分批生成用例
- 外部维护的测试设计用 **XMind 导入**；禅道半成品 XLSX 用 **功能用例库导入**
- Agent 探索模式适合摸底，CI 用稳定录制/编排步骤
- 关注 **首页看板** Token 消耗与生成趋势

## 常见问题

**Q：生成很慢或失败？**  
检查模型配置与网络；大文档用批量任务，勿重复提交。

**Q：导出禅道字段不对？**  
检查项目禅道模板与 Tab「配置」中的字段映射。

**Q：筛选测试点感觉对不上？**  
主模块、子模块为 **精确匹配**；关键词才模糊搜索。

**Q：UI 转完步骤不能跑？**  
到 UI 用例编辑检查定位与环境 URL；必要时录制修正。

**Q：MCP 查不到环境变量？**  
MCP 能力按版本迭代，网页 **环境配置** 中可查看完整全局变量。

**Q：智能浏览器卡在 wait/截图循环？**  
改写任务为可点击路径；平台连续 4 步无进展会自动停止。详见 [智能浏览器](./browser-lab.md)。

**Q：智能浏览器开 Vision 很慢？**  
browser-use 每步都发截图，VL 模型推理重；可关 Vision + 写清 DOM 路径，或换更快模型。详见 [智能浏览器](./browser-lab.md)。

**Q：查看 GIF 跳到登录页？**  
须使用 Hash 链接 `/#/browser-lab/gif/{id}?project_id=...`；升级最新前端后从报告/执行页点击即可。

**Q：问答评测合并后题数变少？**  
合并按 **题目序号去重**，同一序号多批只保留一条（后一次覆盖前一次），不是 4+2=6 简单相加。

**Q：点「选未覆盖」后章节树显示不对？**  
平台会先刷新覆盖统计再同步树勾选；若仍异常，可点 **清空** 后重新 **选未覆盖**，或手动核对下方「已选 N 个章节」与覆盖检查数字是否一致。

**Q：「选未覆盖」与「补充生成」有什么区别？**  
「选未覆盖」只帮你**勾选**还没有对应用例的章节；「补充」在生成时把同批次已有用例摘要发给模型**追加**新用例，不删旧数据。补缺口时通常先选未覆盖 → 入队 → 对该批开启补充。
