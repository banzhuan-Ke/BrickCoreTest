# 版本更新记录

本文记录 BrickCore 各版本的主要功能变更、问题修复与升级指引。当前演示环境平台版本为 **BrickCore v1.3.0**（页脚与 `GET /runner/version` → `platform_version`）。

---

## v1.3.0（2026-07-11）

> **适用**：自 **v1.2.0** 升级至 **v1.3.0**  
> **平台版本号**：**v1.3.0**  
> **建议执行器**：BrickCoreRunner **v1.4.0** 及以上（Web）

### 概览

v1.3.0 在 v1.2.0 基础上新增交互调试、智能浏览器增强、平台配置聚合与 Embedding 配置，并同步更新了使用文档。迭代资料库仍在完善，本期暂不开放。

### 新增功能

- **交互调试**：Web 用例编辑页支持先打开浏览器、手动就位、按步试跑、多步调试，以及定位器拾取与回填
- **UI 自愈 / AI Act**：支持步骤 intent、AI Act 兜底、运行弹窗开关，结果可写回用例，并纳入 AI 场景配置
- **智能浏览器增强**：支持 AI 优化任务描述、执行记录与 GIF 回放，探索结果可导入 Web 自动化用例
- **Embedding 配置**：支持 Embedding 模型、向量维度、默认项与连通性测试

### 改进优化

- **平台配置入口聚合**：AI 模型、执行与自愈、MCP Server、SSE 解析、执行器发布、登录页等统一到「系统管理 → 平台配置」
- **文档更新**：快速开始、智能浏览器、MCP 接入、平台使用帮助等说明已同步
- **迭代资料库**：本期暂不开放入口与正式文档，后续版本单独发布

### 问题修复

- **交互调试**：修复多段结果合并、会话关闭、初始 URL 解析、Runner 回调 401、步骤截图加载失败等问题
- **旧版调试**：修复 `CaseDebugDialog` 模板问题与部分收尾异常
- **运行体验**：补齐调试提示、AI Act 运行提示，以及部分浏览器调试边界处理
- **构建与启动**：修复前端路由中文乱码导致的打包失败、后端语法错误，以及资料库相关迁移在社区版中的兼容问题

### 升级说明

1. 确认 `PLATFORM_VERSION=1.3.0`
2. 建议 `RUNNER_CLIENT_VERSION_LATEST=1.4.0`
3. 若从 v1.2.x 升级：重新构建前端，执行 `aerich upgrade`

**验证**：页脚显示 **v1.3.0**；交互调试与 Embedding 配置可用。

## v1.2.0（2026-07-04）

> **适用**：自 **v1.1** 升级至 **v1.2.0**（含 v1.1.1 补丁能力）  
> **平台版本号**：**v1.2.0**  
> **建议执行器**：BrickCoreRunner **v1.3.16** 及以上（Web；引擎 **v1.0.2**）

### 概述

v1.2.0 是一次**平台大版本同步**，在 v1.1 基础上纳入 v1.1.1 补丁、Web 稳定性修复，并同步 **App 自动化平台侧**能力（菜单、用例编排、数据模型等）。

**公开仓库说明**：

- **App 真机执行**需含 **AppEngine** 的整包 Runner；本仓库不含 `runner/` 引擎源码，网盘 Runner 当前以 **Web 能力**为主。  
- App 菜单与用例管理可在演示环境体验编排；真机调度与执行需整包 Runner（含 App 引擎）或关注后续 Runner 分发说明。  
- **SSE 流式解析配置**可在 **平台配置 → SSE 解析配置** 管理（压测流式等场景复用）。

### 一、平台通用

**执行报告（v1.1.1）**

- 计划报告统计卡片筛选用例；套件报告「返回计划报告」  
- 跳过筛选修复；报告页快捷跳转编辑用例/套件  

**Web 自动化**

- **插入步骤片段无数据**回归修复（`uiFragmentApi.list` 别名）  
- 录制与 AI 自愈加固（需 Runner **v1.3.16+**）：候选打分、表格行锚定、iframe 前缀、`get_by_role` 解析修复  

**搜索与助手**

- 站内搜索、AI 小助手增强；文档中心链接修复  

### 二、App 自动化（平台侧已同步，真机执行需 AppEngine Runner）

> 升级后可见 **App 自动化** 菜单（用例、元素库、元素探查、套件、计划、定时任务、片段、执行记录）。  
> 数据库迁移 **#100～#104** 会创建 App 相关表结构；**无 AppEngine 时无法完成真机调度与执行**。

| 能力 | 平台编排 | 真机执行 |
|------|----------|----------|
| 用例 / 套件 / 计划 CRUD | ✅ | 需整包 Runner + AppEngine |
| 元素库 / 元素探查 UI | ✅ | 探查/投屏需 AppEngine Runner |
| 计划并行 / 定时任务 / 片段 | ✅ 编排 | 需 AppEngine Runner |
| HTML 报告 / 邮件推送 | ✅ 配置 | 需 AppEngine Runner |

App 完整能力（AI 步骤生成、scrcpy 投屏、录屏加固等）需使用含 AppEngine 的整包 Runner 与对应部署环境。

### 三、公开仓库与完整部署差异

| 维度 | 公开仓库（本仓） | 完整部署（含执行器能力） |
|------|------------------|------------------------|
| 平台源码 | `frontend` + `backend` | 同左 |
| 执行器能力 | ❌ 不含内置执行器引擎目录 | ✅ 需配套完整执行器包 |
| SSE 解析配置 | ✅ 平台配置可管理 | ✅ 同左 |
| 内置文档 | 部分演示 stub 覆盖（本页等） | 含内部设计文档 |
| 测试目录 | 不含 `backend/tests/` | 含完整测试 |

### 四、升级步骤

```bash
git pull
cd frontend && npm install && npm run build && cd ..
docker compose up -d --build
docker exec -it fastapi_backend aerich upgrade
```

1. 确认 `PLATFORM_VERSION=1.2.0`；Web 场景建议 `RUNNER_CLIENT_VERSION_LATEST=1.3.16`  
2. 下载最新 **BrickCoreRunner** 网盘包并重新上线  
3. 迁移 **#97～#104**（含最后更新人、测试文件夹、App 表等）  

**验证**：页脚 **v1.2.0**；Web「插入片段」有数据；UI 报告筛选正常；Runner ≥ 1.3.16。

### 五、兼容性

| 项 | 说明 |
|----|------|
| 数据库 | 必须 `aerich upgrade`（#97～#104） |
| 执行器 | Web 建议 **v1.3.16+**；App 真机需 **v1.4.0+** 整包（含 AppEngine） |
| 用例数据 | 向前兼容 |

## v1.1（2026-06-23）

> **适用**：自 **v1.0** 升级至 **v1.1**  
> **平台版本号**：**v1.1**  
> **建议执行器**：BrickCoreRunner **v1.3.15** 及以上（引擎 **v1.0.2**）

### 概述

v1.1 是一次**以 Web 自动化为主、覆盖平台与执行器全链路**的版本更新。主要方向：

1. **测试资源管理升级** — 文件夹上传、多文件上传、测试文件管理页重构  
2. **用例编排提效** — 多选生成片段、步骤复制、套件/计划编辑搜索与「已加入」标识  
3. **录制与定位体系加固** — 弹窗/iframe/特殊字符定位、AI 自愈、表格隐藏行处理  
4. **执行引擎全面稳定** — 30+ 种步骤关键字统一「优先可见元素」策略  
5. **运行环境与分发** — 无头模式、macOS 安装文档、SPA 页面后退/刷新深度兼容  
6. **协作与数据补齐** — 最后更新人字段、性能列表稳定性  

### 一、UI 测试资源管理

**测试文件夹（新）**：整目录上传 MinIO、步骤文件夹模式、中文路径与下载还原修复。

**单文件增强**：多文件模式、自定义显示名、多文件选择器。

**管理页重构**：单文件 / 文件夹分 Tab；兼容 `${{files_path}}`；预签名 URL 下载。

### 二、用例编排与套件编辑

- 多选步骤生成可复用 **片段**（可替换为片段引用）  
- 步骤复制、套件编辑 **左右分栏**  
- 计划/套件编辑：**名称搜索** + **「已加入」** 标识  

### 三、列表协作与数据字段

- 用例、套件、计划列表 **最后更新人**（迁移 **#97**）  
- 用例编辑跳转优化  

### 四、UI 录制与定位

弹窗链式定位、特殊字符转 `get_by_text=`、iframe 原生定位、AI 自愈规范化与 **优先可见元素**。

### 五、执行引擎（Runner）稳定性

> 需 **v1.3.15+**。

- 30+ 步骤关键字 **优先可见元素**；点击类失败 `force` 重试  
- SPA：**history.back()** 后退、`domcontentloaded` 刷新、**提取当前页面 url**、`fallback_url`  
- hover：`timeout` 仅定位超时，停留 `wait_time` 默认 500ms  
- 失败步骤报告序号修正；Linux **无头模式**  

### 六、AI 能力

AI 探索 / 录制 Prompt 同步导航步骤说明（后退、提取 URL 等）。

### 七、性能测试

修复执行记录列表 `sort buffer` 溢出；定时压测查询优化。

### 八、执行器分发

客户端 **v1.3.15**；macOS arm64 / Intel 包与安装指南；设备管理升级提示。

### 九、部署与运维

平台版本 **v1.1**；`restart.sh` 分支自适应；迁移 **#97**、**#98**。

### 十、升级步骤

```bash
git pull
cd frontend && npm install && npm run build && cd ..
docker compose up -d --build
docker exec -it fastapi_backend aerich upgrade
```

下载最新 **BrickCoreRunner** 并重新上线；确认 `RUNNER_CLIENT_VERSION_LATEST=1.3.15`。

**验证**：页脚 v1.1、测试文件双 Tab、片段生成、最后更新人、编排「已加入」、Runner ≥ 1.3.15。

### 十一、兼容性

| 项 | 说明 |
|----|------|
| 数据库 | 必须 `aerich upgrade` |
| 执行器 | 建议 **v1.3.15+** |
| 用例数据 | 向前兼容 |

### 十二、使用建议

1. 虚拟列表用语义化定位，避免纯 `(//xpath)[1]`  
2. 悬停菜单：hover → 等待 500~1000ms → click  
3. SPA 无历史时用新标签或 `fallback_url`  
4. macOS 须在 Mac 本机解压对应芯片包
