# Token 授权

## 适用场景

接口需先 **登录** 获取 Token（或 `tenant_id`、`session` 等）再访问业务 API 时，在本功能统一维护登录态。执行用例前自动注入，避免每条用例重复登录。

## 何时不必建授权

若 Token 已写在 **项目配置 → 环境** 的 `global_vars` 中（或长期固定不变），用例里直接引用即可，例如：

```http
Authorization: Bearer ${{access_token}}
```

无需再建 Token 授权。本功能适合 **需要定期登录刷新、多角色多套 Token** 的场景。

## 变量优先级（同名变量谁生效）

执行单条用例时，平台按以下顺序合并变量（**后面的覆盖前面的**）：

| 优先级（低 → 高） | 来源 | 说明 |
|-------------------|------|------|
| 1 | 项目全局变量 | 项目配置中的 `global_vars` |
| 2 | 环境变量 | 环境配置中的 `global_vars` |
| 3 | 套件/计划传递变量 | 套件串行执行时，**前面用例提取**的变量传给后续用例 |
| 4 | **Token 授权** | 本页配置的登录态，执行前自动注入（如 `token`） |
| 5 | 前置脚本 | 用例 `pre_script` 可再次修改变量 |

**重要：**

- 若 **Token 授权已启用** 且提取变量名为 `token`，则 **授权注入会覆盖** 环境变量和同名的套件传递变量。
- **不要** 在同一环境下同时使用「套件第一条登录用例 extract token」与「Token 授权 extract token」且变量同名——请 **二选一**。
- 多角色请用不同变量名（如 `admin_token`、`user_token`），同一环境 **仅一条授权可启用**（取最近更新的一条）。

**推荐选型：**

| 场景 | 建议 |
|------|------|
| Token 会过期，全项目统一登录 | 只用 **Token 授权**，套件不必放登录用例 |
| Token 长期固定 | 只写在 **环境变量**，关闭 Token 授权 |
| 按套件流程登录、不用授权 | **关闭 Token 授权**，第一条用例登录并 extract |

## 配置入口

**路径**：**接口自动化 → Token 授权**

页顶可按 **环境** 筛选；每个授权绑定 **一个环境**（创建后不可改环境）。同一环境可配置多条授权（不同登录身份），用例侧引用不同变量名即可。

## 配置步骤

### 1. 新建授权

点击 **新建授权**：

| 字段 | 说明 |
|------|------|
| 授权名称 | 如「测试环境-管理员 Token」 |
| 环境 | 该授权生效的环境 |
| 登录接口 + 提取规则 | 默认 **接口登录** 方式，见下文 |
| 有效期 | Token 缓存时长（分钟） |
| 提前刷新 | 距过期多少分钟时自动重新登录 |
| 启用 | 关闭后不再自动刷新 |

### 2. 接口登录（推荐，默认）

1. 选择 **接口管理** 中已维护的登录接口（需能在接口编辑页 **调试/发送** 成功）
2. 配置 **变量提取规则**，从响应取 Token，例如：

| 变量名 | 来源 | 表达式示例 |
|--------|------|------------|
| token | JSON | `$.data.token` |
| tenant_id | JSON | `$.data.tenantId` |
| session | Header | `Set-Cookie` 或具体 Header 名 |

按实际响应结构调整路径；支持 JSON / Header / 正则三种来源。

### 3. 自定义代码（高级选项）

展开对话框底部 **高级选项** 可切换为 **自定义代码**。**仅适合**从环境 `global_vars` 拼变量或写入固定 Token，**不能发 HTTP 请求**。需要调登录接口时请改回 **接口登录**。

编写 `auth(context)` 并返回字典：

```python
def auth(context):
  # context 含环境变量等
  return {
    "token": context.get("fixed_token", ""),
    "tenant_id": "14"
  }
```

### 4. 调试、保存与刷新

1. 配置完成后点击 **调试授权**：不写入缓存，弹窗展示本次提取到的变量（或错误信息）
2. **保存** 后，在列表点击 **刷新** 触发一次正式登录并写入缓存
3. 打开 **缓存** 查看 `token` 等字段；失败时查看 **最近错误**

### 5. 在用例中引用

请求头或参数中使用：

```http
Authorization: Bearer ${{token}}
```

或 Query：`tenantId=${{tenant_id}}`

执行前系统自动检查缓存；即将过期时 **自动重新登录**（并发时仅一个任务刷新，其余等待）。

## 与测试计划的关系

- Token 在 **环境维度** 缓存，同一环境下调度套件、计划、定时任务 **共享** 同一份授权缓存
- 切换环境会使用对应环境的授权配置

## 常见问题

**Q：环境下拉为空？**  
先在顶部栏选择 **项目**，并在 **项目配置 → 环境** 中创建环境；授权页与环境配置共用同一环境列表。

**Q：刷新失败？**  
先用 **调试授权** 或 **接口管理** 单独调试登录接口；检查账号密码是否在环境变量中；确认 JSONPath 能匹配响应。

**Q：自定义代码报「不能发 HTTP」？**  
自定义代码沙箱不支持请求外部接口，请改用 **接口登录**，或把 Token 预先写在环境变量里。

**Q：用例仍 401？**  
确认用例选择了正确环境；请求头格式 `Bearer ${{token}}` 中间有空格；授权是否启用。

**Q：并发会重复登录吗？**  
不会。多任务同时发现过期时，仅一个执行刷新，其他等待新 Token。

**Q：如何停用？**  
关闭 **启用** 开关，或 **清空缓存** 后不再配置刷新。

**Q：多角色多套 Token？**  
可建多条授权，提取为不同变量名（如 `admin_token`、`user_token`），用例分别引用。同一环境仅一条授权处于启用状态时生效。

**Q：套件里已有登录用例提取 token，还要配 Token 授权吗？**  
一般 **不必二选一**。若两处都配且变量同名（如都叫 `token`），**Token 授权优先**，前序用例提取的值不会传到后续用例。需要链式登录时请关闭 Token 授权；需要平台自动刷新时请用 Token 授权并去掉套件登录用例。

**Q：环境变量里写了 token，和授权冲突吗？**  
同名时 **Token 授权覆盖环境变量**。环境变量适合放 host、账号等静态配置；动态 Token 建议只走授权或只走环境，不要重复配置。
