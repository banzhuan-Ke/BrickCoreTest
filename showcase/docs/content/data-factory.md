# 数据工厂

## 适用场景

接口 JSON 断言无法验证「数据是否落库正确」；Web UI 操作后也常需核对数据库状态。**数据工厂**提供：

- **环境级数据源**：按项目 + 环境配置 MySQL 连接
- **SQL 模板**：setup（造数）/ teardown（清数）/ query（查询）
- **库断言**：执行后只读 SELECT 校验行数、字段值、存在性
- **套件 Hooks**：接口/UI 套件执行前后自动跑 SQL

**路径**：**接口自动化 → 数据工厂**  
**权限**：角色需勾选 `data_factory:view`（查看/测试）、`data_factory:edit`（新建/编辑/删除）

## 密码与安全存储

| 项目 | 说明 |
|------|------|
| **存储方式** | 数据库密码以 **Fernet 对称加密** 写入 `password_encrypted` 字段，**明文不落库** |
| **密钥来源** | 优先 `AI_API_KEY_SECRET` 环境变量；未配置时由 Backend `SECRET_KEY` 派生（与 LLM API Key 等同套加密模块） |
| **接口返回** | 列表/详情仅返回 `has_password: true/false`，**不回传密码明文** |
| **编辑行为** | 编辑时密码框留空表示「不修改」；填写新密码才会更新密文 |
| **测试连接** | 弹窗内「测试连接」**不会先写库**，仅临时用表单密码测连通；**须点「保存」才会持久化** |

> Docker 部署时，数据源「主机」填容器网络名 `mysql`（不是 `127.0.0.1`）；端口 `3306`。

## 配置数据源

1. 点击 **新建数据源**，选择 **环境**（创建后不可改环境）
2. 填写主机、端口、库名、用户名、**密码**（新建必填）
3. 可选：**允许写操作**（setup/teardown 需要 INSERT/UPDATE/DELETE 时勾选）
4. 点击 **测试连接** 确认连通（可选）
5. 点击 **保存** — 密码加密写入数据库

列表页 **测试** 使用已保存的密文密码连接，无需再次输入。

### 常见问题

**Q：弹窗测试成功，列表再测失败？**  
测试成功但未点 **保存**，密码未入库。请编辑后重新输入密码并 **保存**。

**Q：编辑时密码框是空的？**  
出于安全，编辑不回显密码。若已配置过（`has_password=true`），留空则不修改；若要改密码，重新输入后保存。

## SQL 模板

**类型**：

| 类型 | 用途 | 写操作 |
|------|------|--------|
| setup | 套件/用例执行前造数 | 需数据源允许写 |
| teardown | 执行后清数 | 需数据源允许写 |
| query | 调试查询 | 只读 |

SQL 支持变量替换：`${{变量名}}`（与接口用例变量语法一致）。

## 库断言

在用例或套件编辑页配置 **数据库断言**：

- 仅允许 **SELECT** 类 SQL
- 支持运算符：`equals`、`row_count_equals`、`exists` 等
- 用例编辑页可 **调试断言** 后保存

断言结果写入执行报告；HTML 导出含 **数据工厂 Hooks** 区块。

## 与套件 / 计划联动

### 接口自动化

| 阶段 | 时机 |
|------|------|
| setup SQL | 套件用例循环 **之前** |
| teardown SQL + 套件级断言 | 全部用例 **之后** |
| 用例级库断言 | 单条用例执行 **之后** |

已接入：手动/批量执行、测试计划、定时任务（套件模式）。

### UI 自动化

| 阶段 | 执行位置 |
|------|----------|
| setup SQL | 平台派发 MQ **之前** |
| teardown + 套件断言 | Runner 套件完成后 **回调** Backend |

UI 后置 SQL/断言需 Runner **≥ 1.1.0** 且配置与 Backend 一致的 `INTERNAL_API_KEY`。旧 Runner 不影响基础 UI 执行，仅跳过 teardown/断言。

## 使用建议

1. 每个环境至少配置一个 **默认数据源**（可选勾选「设为环境默认」）
2. 只读校验场景 **不要** 勾选「允许写操作」
3. teardown 模板与 setup 成对维护，避免测试数据残留
4. 复杂造数可拆成多条 setup 模板，按 ID 顺序执行
